## Two objects that typeof cannot tell apart

Last chapter, `typeof` told a number from a string. Now suppose a
drawing program has circles (with a radius `r`) and rectangles (with a
width `w` and height `h`). Ask `typeof` about either and the answer is
the same, `'object'`, so it cannot help us work out an area. The fix is
to put the answer inside the object: every shape carries a field saying
which kind it is.

<Analogy title="tickets with the type printed on top">
A train ticket has “SINGLE” or “RETURN” printed across the top. The
inspector reads that word first, and it says which other details to
look for: a return ticket has a return date, a single does not.
<span slot="breaks">A ticket can be misprinted or forged, and the
inspector may notice; the checker trusts the tag completely, so data that
arrives from outside with a wrong tag (types are erased, after all) is
still possible, and needs a run-time guard.</span>
</Analogy>

```ts
type Shape =
  | { kind: 'circle'; r: number }
  | { kind: 'rect'; w: number; h: number };

function area(s: Shape): number {
  if (s.kind === 'circle') {
    return Math.PI * s.r * s.r;
  }
  return s.w * s.h;
}
```

Line 1 uses `type`, which names any type (like `interface`, but it can
name a union too). Lines 2 and 3 are the two variants. In
`kind: 'circle'`, the type is not “any string” but the exact string
`'circle'` and nothing else, a **literal type**; that is what makes
`kind` a tag. Line 5 checks the tag, so the checker narrows `s` to the
circle variant on line 6, where `s.r` is allowed; line 6 returns, so on
line 8 only a rectangle is left, and `s.w` and `s.h` are allowed.

<Callout kind="definition">
A **literal type** such as `'circle'` allows exactly one value. A
**discriminated union** (also called a *tagged union*) is a union of
object types that all share one property, the **tag** (here `kind`),
with a different literal type in each variant. Checking the tag narrows
the whole object to one variant<Cite id="ts-narrowing" />.
</Callout>

<Formal title="Narrowing by tag">

```text
s : Circle | Rect
s.kind === 'circle'  ⟹  s : Circle
s.kind !== 'circle'  ⟹  s : Rect
```

<span slot="read">Writing Circle for the variant with kind 'circle' and
Rect for the other: s is one of the two. Where the test “s's kind is
circle” has passed, s is a Circle (the arrow ⟹ reads “means that”);
where it has failed, s is a Rect.</span>
</Formal>

<Examples of="discriminated-union">

```ts
type Light =
  | { kind: 'off' }
  | { kind: 'on'; level: number };
```

```ts
type Parsed =
  | { ok: true; value: number }
  | { ok: false; error: string };
function show(p: Parsed) {
  if (p.ok) return 'got ' + p.value;
  return 'failed: ' + p.error;
}
```

</Examples>

In the first, a light that is off has no other data, and one that is on
also has a brightness, so `level` exists only where it makes sense. In
the second the tag is `ok`, with the literal types `true` and `false`: a
result that worked (and has a `value`) or failed (and has an `error`),
which is how a parser can report a mistake without throwing. The
runnable one is `area` on a list of shapes; try a shape with a new kind.

Reading a field before checking the tag is the usual slip:

```ts
const r = s.r; // s is a Shape
// error: Property 'r' does not exist on
// type 'Shape'.
```

A rectangle has no `r`, so the checker refuses until you check
`s.kind === 'circle'` first.

## The shape of every syntax tree

Here is why this matters for the rest of the book. Once a parser has
read a program, the code becomes a **tree** (the trees chapter's
nodes holding child nodes), and every node is one of a fixed set of
kinds. That is a discriminated union, one that refers to itself:

```ts
type Expr =
  | { kind: 'num'; value: number }
  | { kind: 'add'; left: Expr; right: Expr }
  | { kind: 'mul'; left: Expr;
      right: Expr };
```

<Figure takeaway="A syntax tree is a discriminated union, nested." caption="(1 + 2) * 4 as Expr objects. Each node's kind says which variant it is; add and mul nodes hold two smaller Expr nodes, so the type refers to itself.">
  <ExprTree />
</Figure>

A `num` node holds a number; an `add` or `mul` node holds two smaller
expressions, each of which may be any kind of `Expr`. Real tools work
this way: in ESTree, the tree format many JavaScript tools share, every
node has a string `type` field naming its kind<Cite id="estree" />. To
work out a tree's value, check the tag: a `num` is the base case, and an
`add` or `mul` first works out both children (recursively), then
combines them:

## Proving every case is handled

Suppose you add a third shape, `{ kind: 'tri'; b: number; h: number }`,
and forget to update `area`. It would quietly treat a triangle as a
rectangle and compute `s.w * s.h`, which is `NaN` (not a number), since
a triangle has no `w`. We want the checker to point at the gap.

<Analogy title="packing from a list">
Before a trip you cross items off a packing list as they go into the
bag. An empty list means everything is packed; any item still on it is
exactly what you forgot.
<span slot="breaks">You might cross something off and leave it on the
bed; the checker crosses off a variant only with a check that returns,
so crossed off always means handled.</span>
</Analogy>

TypeScript has a type for “nothing is left”: **`never`**, the type with
no values at all. A function whose parameter is `never` can only be
called where nothing is left, so it makes a perfect end to the list:

```ts
function unreachable(x: never): never {
  throw new Error('unhandled kind');
}

function area(s: Shape): number {
  if (s.kind === 'circle') {
    return Math.PI * s.r * s.r;
  }
  if (s.kind === 'rect') return s.w * s.h;
  return unreachable(s);
}
```

Each check that returns removes one variant. With `Shape` having circle,
rectangle and triangle, the last line is reached with `s` still possibly
a triangle, so `tsc` reports `Argument of type '{ kind: "tri"; b: number;
h: number; }' is not assignable to parameter of type 'never'`.

<Figure takeaway="Each check removes a variant; never means none are left." caption="The type of s as the checks run. Forget tri, and unreachable is handed a tri, which is an error. Handle tri, and nothing is left: never.">
  <ShrinkToNever />
</Figure>

Add `if (s.kind === 'tri') return s.b * s.h / 2;` and nothing is left
for `s` to be on the last line, so `s` is `never` and the call is
accepted.

<Callout kind="definition">
**`never`** is the type with no values. **Exhaustiveness checking**
makes the checker prove that every member of a union is handled: after
all the checks, the leftover type must be `never`, which
`unreachable(s)` demands<Cite id="ts-narrowing" />. Keep the `throw`
inside it anyway, for bad data at run time.
</Callout>

<Formal title="Exhaustiveness as subtraction">

```text
Shape − circle − rect − tri = never   ✓
Shape − circle − rect       = tri     ✗
```

<span slot="read">Start from all the variants of Shape and take away
each one a check handled. If nothing is left, the type is never and
every case is handled; if tri is left, the checker reports tri as the
missing case.</span>
</Formal>

<Examples of="exhaustiveness">

```ts
function watts(l: Light): number {
  if (l.kind === 'off') return 0;
  if (l.kind === 'on') return l.level * 9;
  return unreachable(l);
}
```

```ts
const s = JSON.parse('{"kind":"hex"}');
area(s);
// Error: unhandled kind
```

```ts
type Instr =
  | { op: 'load'; slot: number }
  | { op: 'add' }
  | { op: 'store'; slot: number };
```

</Examples>

The first uses `Light` from earlier: both kinds are handled, so
`l` is `never` on the last line and the code is accepted. The second
shows why the `throw` stays: `JSON.parse` (which turns text into an
object) makes data the checker knows nothing about, so a shape of kind
`'hex'` reaches `area`, and `unreachable` stops with a clear message
instead of returning `NaN`. The third is how
compilers use it: the instructions of a virtual machine are a tagged
union (here tagged by `op`), and the moment you add a new instruction,
every function that ends in `unreachable` but forgot it becomes an
error.

## What you learned

- A **discriminated union** gives every variant a shared **tag** field
  with its own **literal type**; checking the tag narrows the object to
  one variant, and only then are its fields allowed.
- A syntax tree is a discriminated union that refers to itself;
  evaluating one is a recursive walk with `num` as the base case.
- **`never`** has no values. **Exhaustiveness checking**: end with
  `unreachable(x: never)`, and the checker proves every case is
  handled. Keep the run-time `throw` too.
