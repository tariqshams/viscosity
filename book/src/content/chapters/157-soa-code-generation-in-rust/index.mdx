## From a plan to a program

The planner has decided that `ps` should become a struct of arrays. Now
something has to write the program that does it: a class to hold the
columns, and a new spelling for every place the program creates, grows
or reads `ps`. In the TypeScript engine that was *Generating SoA
storage* and *Rewriting field accesses and growing collections*; in Rust
it is `crates/frontend-js/src/emit.rs`. Here is a program:

```js
const ps = [];
for (let i = 0; i < 100; i++)
  ps.push({ x: i, vx: 1 });
for (let i = 0; i < ps.length; i++)
  ps[i].x += ps[i].vx;
console.log(ps[99].x);
```

and the end of what `viscosity build` wrote for it (Rust CLI, release
build, rustc 1.97; the TypeScript CLI wrote the same bytes, and node
prints `100` for both versions):

```js
const ps = new __Vsc_ps();
for (let i = 0; i < 100; i++)
  ps.push(i, 1);
for (let i = 0; i < ps.length; i++)
  ps.x[i] += ps.vx[i];
console.log(
  ps.x[__vsc_bc(ps, 99, 'x', false)]);
```

Everything the program didn't need to change is where it was; above
it, the emitter put a class, `__Vsc_ps`, and a helper, `__vsc_bc`.

## The container class

For each collection planned as SoA, `container_class` builds the class
with `format!` and `join`. Reformatted (it is six long lines in the
output), with `of` and `grow` shortened:

```js
class __Vsc_ps {
  constructor(cap = 16) {
    this.length = 0; this.cap = cap;
    this.x = new Float64Array(cap);
    this.vx = new Float64Array(cap);
  }
  static of(...v) { … }
  push(v0, v1) {
    const n = this.length;
    if (n === this.cap) this.grow();
    this.x[n] = v0; this.vx[n] = v1;
    return (this.length = n + 1);
  }
  grow() { … }
}
```

`length` is how many elements are in use and `cap` how many slots each
column has. `push` takes the values in field order, grows the columns
when they are full, writes slot `n` of each, and returns the new length,
as `Array.prototype.push` does. `grow` doubles `cap`, makes new typed
arrays and copies the old ones in with `set`; `of` builds a container
from an array literal's values.

## Names that never clash

Two collections can have the same name in different functions, so the
class name is numbered (from `emit_js`):

```rust
let mut cls = format!("__Vsc_{}", c.name);
let mut k = 2;
while class_names.contains(&cls) {
    cls = format!("__Vsc_{}_{k}", c.name);
    k += 1;
}
class_names.insert(cls.clone());
```

`class_names` is a `HashSet<String>` of names already used, so the
corpus program `same_name_collections.js` gets `__Vsc_ps` and
`__Vsc_ps_2`. Columns need more care, because they are properties of
the container: a field called `length` or `push` would overwrite the
container's own members. `column_name(field, i)` keeps a field's name
only if it is a plain ASCII identifier and not in the list `RESERVED`
(`length`, `push`, `grow`, `of`, `constructor`, `prototype`, `get`,
`cap`, `data`); otherwise field number `i` becomes `f{i}_`. Then
`column_names` makes the list unique: a renamed column gets `_` appended
until it differs from every field that kept its name and every column
before it. The corpus program `renamed_column_clash.js` has fields
`length` and `f0_`, so `length` (field 0) would become `f0_`, which the
real field already uses, and becomes `f0__`.

An element read that wasn't proven in bounds goes through `__vsc_bc(c,
i, f, w)`, which returns `i` when `i >>> 0 === i && i < c.length` (a
whole number from 0 up, below the length) and otherwise throws the same
`TypeError`, word for word, that the original would have thrown reading
`.f` of `undefined`; the flag `w` picks the "setting" wording for writes.

<Callout kind="definition">
**SoA emission in Rust** (`emit.rs`) writes one **container class** per
transformed collection, `__Vsc_name` (numbered `__Vsc_name_2`, ... on a
clash), with one **column** per field named by `column_names` (`f{i}_`
for reserved or non-identifier names, then made unique), and rewrites
the program as a list of **byte-range edits** applied **back to front**.
Accesses not proven in bounds index through **`__vsc_bc`**, which throws
the original's `TypeError`; writes whose order could be observed **store
late**.
</Callout>

<Examples of="rust-soa-codegen">

```js
const p = ps[i];
p.x *= 2;
// → const p = i;
//   ps.x[p] *= 2;
```

</Examples>

This is real output of the Rust CLI, for an `i` proven in bounds. A
variable that held an element now holds the element's *index*: the
edit for `ps[i]` in the declaration replaces the whole read with `i`,
since there is no object to fetch any more, and every access through
`p` becomes an index into a column, so `p.x` becomes `ps.x[p]`. The
`*= 2` is untouched text, copied through as it was. This is how the hot
loop of the benchmark `particles.js`, `const p = arr[i]; p.x += p.vx *
dt;`, is compiled.

<More title="More: array literals and for...of">

```js
const ps = [{ x: 1, vx: 2 },
  { x: 3, vx: 4 }];
// → const ps = __Vsc_ps.of(1, 2, 3, 4);
for (const p of ps) s += p.x;
// → for (let p = 0; p < ps.length;
//     p++) s += ps.x[p];
```

An array literal becomes a call to `of`, with the values in field order
(compiled with `--min-size 0`, since two elements are below the
threshold). A `for...of` loop becomes a counting loop whose variable
holds an index.

</More>

## A write that failed too early

For reads, `__vsc_bc` is the whole story. For writes it is not, and the
corpus program `write_rhs_first.js` is there to show why: a fuzzer wrote
a program like it. Its core is `ps[100].x = (t = 5)` inside a `try`,
with `ps` holding 100 elements. The original prints `caught Cannot set
properties of undefined (setting 'x') 5`; the old emitter's
`ps.x[__vsc_bc(ps, 100, 'x', true)] = (t = 5)` printed the same message
with `0`, because it threw before the right-hand side ran.

For an assignment `a = b`, the specification evaluates the left-hand
side to a **reference** (here, "property `x` of the value `ps[100]`"),
then the right-hand side, and only then stores, with `PutValue`; and it
is `PutValue` that throws when the base is
`undefined`<Cite id="ecma262-assignment-order" />. The rewritten left
side is also evaluated first, but now that *runs the check*. The same
order caused a quieter bug: evaluating `ps.x[...]` also fetches the
column, and if the right side pushes and the container grows, `grow()`
replaces `this.x`, so the store goes into the old array, which nothing
reads any more. Step through it on `ps[3].x = (more(), 77)`, where
`more()` pushes:

<Analogy extra title="a waiter and a moved table">
A waiter takes your order and only walks to your table once the plate
is ready. If the table was moved while the food was cooking, he looks
for it again; he doesn't set the plate down where the table used to be.
<span slot="breaks">A waiter can see the room; the compiled code can't
"look again" unless the emitter wrote it to fetch the column at the
moment of the store, which is exactly what the fix does.</span>
</Analogy>

The fix starts in the analysis. For every field write it records what
evaluating the rest of the assignment can do, as an enum ordered from
least to worst (doc comments left out):

```rust
#[derive(Copy, Clone, PartialEq, Eq,
    PartialOrd, Ord, Debug)]
pub enum RhsEffect {
    Inert,
    MayThrow,
    Effects,
}
```

Deriving `PartialOrd` and `Ord` orders the variants as they are written,
`Inert < MayThrow < Effects`, so the analysis combines the parts of a
right-hand side with `worst = worst.max(effect(x))`. Constants,
variables and arithmetic on numbers are `Inert`; an unproven element
read is `MayThrow`; a call, an assignment such as `t = 5`, or anything
unmodelled is `Effects`. The emitter then stores late only when the
order can be observed: an unproven `=` whose right side is not `Inert`,
or a typed column (which `grow()` can replace) whose right side is
`Effects`. The late form, `__vsc_set(ps, 'x', __vsc_bk(ps, 100), (t =
5), 'x')`, decides the bounds question first with `__vsc_bk` (which
answers `NaN` instead of throwing), runs the right side as an argument,
and only then throws or fetches the column *as it is now* and stores.

## What you learned

- The **container class** holds `length`, `cap` and one column per
  field; class names are **numbered** on a clash, and columns become
  `f{i}_` when **reserved**, extended with `_` until **unique**.
- Unproven reads go through **`__vsc_bc`**, which returns the index or
  throws the original's error.
- JavaScript evaluates a field write's **reference**, then the
  **right-hand side**, then **stores**; each write's **`RhsEffect`**
  decides whether the emitter **stores late**, through `__vsc_bk` and
  `__vsc_set`.
