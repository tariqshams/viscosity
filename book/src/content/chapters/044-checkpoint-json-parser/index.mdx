## What JSON is

Programs constantly hand data to each other as text: a settings file, a
reply from a server, the profile Viscosity's command line reads. The
most common format for it, readable from every language, is **JSON**<Cite id="rfc8259" />.

```json
{"name": "drip", "tags": ["vm", "gc"],
 "v": 2, "ok": true, "next": null}
```

Every post office can read an address because the format is fixed:

<span slot="breaks">A post office forgives a misspelt street; JSON

<Callout kind="definition">
**JSON** (JavaScript Object Notation) is a text format for data, defined
by RFC 8259<Cite id="rfc8259" />. A JSON value is one of six kinds:
`null`; `true` or `false`; a number; a string in double quotes; an
array, `[` values separated by commas `]`; or an object, `{` members
separated by commas `}`, where each member is a string key, a colon and
a value. Spaces, tabs and line breaks are allowed between any two
pieces. In JavaScript, `JSON.parse` turns JSON text into a value and
`JSON.stringify` turns a value into JSON text<Cite id="mdn-json" />.
</Callout>

<Formal title="JSON's grammar (from RFC 8259, simplified)">

```text
value  = object / array / string
       / number / true / false / null
array  = "[" [ value *( "," value ) ] "]"
object = "{" [ member *( "," member ) ] "}"
member = string ":" value
number = [ "-" ] int [ frac ] [ exp ]
```

<span slot="read">Each line is a rule: the name on the left is made of
what is on the right. A slash means "or"; square brackets mean "this
part is optional"; *( ) means "this part, repeated any number of times,
including none"; text in quotes is those exact characters. So an array
is a "[", then optionally a value followed by any number of comma-value
pairs, then a "]". The chapter on grammars teaches this notation
properly.</span>
</Formal>

JSON.parse('[1, 2]');     // [1, 2]

```

// "[1, 2,]" is not valid JSON

// SyntaxError: Unexpected number in
// JSON at position 1 ...
```

The first goes there and back: text into an array, and an object into
text. The second is the strictness, in
Node's exact words (the `...` hides a line and column): a trailing comma
and a leading zero look like JavaScript, but are not JSON, and nor are
single quotes, comments or `NaN`<Cite id="mdn-json" />. The third is how
Viscosity's command line reads a profile: `JSON.parse` throws a
`SyntaxError` for bad text, which the engine turns into its own message
(shortened to `msg` here). The result is typed `unknown` ("could be
anything; check before use", the safe opposite of `any`), because it came
from outside, and the code after it checks the shape by hand: the border
pattern from the last two chapters. The runnable one prints
`{"n":1,"s":"hi","list":[true,null],"nan":null,"m":{}}`: `NaN` became
`null`, `gone` vanished, and the `Map` became an empty object; the
`\u00e9` escape comes back as `é`.

## The plan: types first

Designing with types says to write the data down first. A JSON value
becomes this type, which refers to itself, just as `Expr` did in the
tagged unions chapter:

```ts
type Json =
  | null | boolean | number | string
  | Json[]
  | { [key: string]: Json };
```

The last line is an **index signature**: an object with any string keys,
each holding a `Json`<Cite id="ts-object-types" />. Turning text into a
`Json` takes two stages, as in every compiler in this book: a
**scanner** cuts the text into **tokens**, the words of JSON (a bracket,
a colon, a number, a string, a keyword), skipping spaces; then, next
chapter, a parser builds the tree. The tokens, each remembering where it
started, for error messages:

```ts
type Punct =
  '[' | ']' | '{' | '}' | ':' | ',';
type Word = 'true' | 'false' | 'null';
type Token =
  | { kind: Punct; at: number }
  | { kind: Word; at: number }
  | { kind: 'num'; value: number;
      at: number }
  | { kind: 'str'; value: string;
      at: number }
  | { kind: 'end'; at: number };
```

Only numbers and strings carry a value; the `'end'` token marks where
the text ran out, so the parser never reads past the last token. Step
through the scanner at work:

<OtherLanguages>

```js
const v = JSON.parse('[1, 2.5]');

```

```python
import json
v = json.loads('[1, 2.5]')
type(v[0]), type(v[1])  # int, float
json.loads('NaN')  # nan, accepted
```

```java
// The Java standard library has no
// JSON parser: programs add a library.
```

```c
/* Nor does C's: a parsed value is
   usually kept as a tagged struct */
struct json { int kind; /* ... */ };
```

</OtherLanguages>

JavaScript and Python both read JSON out of the box, with two real
differences: Python keeps whole numbers and decimals apart (`int` and
`float`) where JavaScript has one number type, and Python's `json.loads`
accepts `NaN`, which is not JSON at all. Java and C leave JSON to
libraries, and in C a parsed value is a tagged struct, a hand-built
version of our `Json` union.

## What you learned

- **JSON** is a strict text format for six kinds of value; trailing
  commas, single quotes, leading zeros and `NaN` are not JSON.
- Types first: a recursive `Json` type with an **index signature** for
  objects, and a `Token` union whose tokens remember where they began.
- A **scanner** cuts text into tokens, following the grammar one
  character at a time, and refuses bad input with a clear error.

Next: the parser, which turns your tokens into a `Json` tree, and the
