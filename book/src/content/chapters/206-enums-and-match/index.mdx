## One of several things

Your TypeScript VM needed “this is one of several things” in three
places, and spelled it three ways. The dispatch loop switched on opcode
numbers:

```ts
switch (instruction) {
  case OP.NIL: this.push(null); break;
  case OP.NEGATE: /* ... */ break;
  // ...
}
```

A value was `null | boolean | number | Obj`, checked with `typeof`
(chapter 78). And when you wanted a tag and a payload, you wrote a
discriminated union (chapter 16):

```ts
type Tagged =
  | { tag: 'nil' }
  | { tag: 'bool'; as: boolean }
  | { tag: 'num'; as: number };
```

Rust has a single feature for all three.

A parcel label with tick boxes: *letter*, *parcel*, *registered*. You
tick exactly one. Some boxes come with a blank to fill in, like
“registered: tracking number ____”, and the blank only exists if you
ticked that box.
</Callout>

## Enums

```rust
enum Op {
    Constant,
    Add,
    Negate,
    Return,
}

enum Value {
    Nil,
    Bool(bool),
    Number(f64),
}

let op = Op::Add;
let v = Value::Number(2.5);
```

These are adapted from the Rust Drip VM. Its `OpCode` (in
`companion/rust/src/chunk.rs`) has 37 variants, and its `Value` (in
`value.rs`) adds variants for strings, functions, classes and other
heap objects.

An `Op` is exactly one of four things. A `Value` is one of three, and
two of those carry data: `Bool` holds a `bool`, `Number` holds an `f64`.
That is the tagged value of chapter 78, written as a type. A variant
can also hold several values, `Pair(f64, f64)`, or named fields like a
struct, `Move { dx: f64, dy: f64 }`<Cite id="klabnik2026" />.

<Callout kind="definition">
An **enum** is a type whose every value is exactly one of a fixed list
of **variants**. A variant may carry data. You name one with a path,
`Value::Number(2.5)`. An enum with data is Rust’s version of a
discriminated union: the variant is the tag, its data is the payload.
</Callout>

## match

To do anything with an enum you ask which variant it is, and take its
data out. That is `match`:

```rust
let n = match v {
    Value::Nil => 0.0,
    Value::Bool(true) => 1.0,
    Value::Bool(false) => 0.0,
    Value::Number(x) => x,
};
```

Each line inside is an **arm**: a pattern, `=>`, and the code to run.

<MatchSteps client:visible />

Three things to notice. Arms are tried top to bottom, and the first one
that fits wins. There is no falling through to the next arm, so there
is no `break` to forget. And `match` is an expression, like `if` in
chapter 201, so every arm produces a value of the same type.

The third is the big one. A `match` must cover **every** possible value.
Leave out `Value::Bool(false)` and you get this (real `rustc` 1.97
output, trimmed):

```
error[E0004]: non-exhaustive patterns:
  `Value::Bool(false)` not covered
```

In TypeScript you can get the same check, but you have to set it up
with a `never` trick (chapter 16). In Rust it is always on, and it is a
hard error, not a warning<Cite id="klabnik2026" />.

<Callout kind="definition">
A **`match`** expression compares a value with the **patterns** of its
arms, in order, and runs the first arm that fits<Cite id="rustref-match" />.
The value and the patterns must have the same type. The match must be
**exhaustive**: every possible value has to fit some arm, or it doesn’t
compile.
</Callout>

## Patterns

The left side of an arm is a **pattern**: a shape the value is compared
with. You have now seen several kinds:

- **Literals**, like `true`, `0` or the byte `b'('`.
- **Variants**, like `Value::Nil`, with patterns for their data inside.
- **Bindings**: a plain name like `x` fits anything and names it.
- **The wildcard** `_` fits anything and names nothing.
- **Or-patterns**: `p | q` fits if either fits.
- **Pairs**: `(p, q)` matches two values at once.

Here is Drip’s truthiness from chapter 53, with an or-pattern:

```rust
fn is_falsey(v: Value) -> bool {
    match v {
        Value::Nil
        | Value::Bool(false) => true,
        _ => false,
    }
}
```

and here is `+` on two numbers, matching a pair. `(a, b)` is a
**tuple**: a few values grouped in parentheses.

```rust
match (a, b) {
    (
        Value::Number(x),
        Value::Number(y),
    ) => Value::Number(x + y),
    _ => Value::Nil, // VM: an error
}
```

The Rust scanner matches on bytes the same way, one arm per character,
like `b'(' => self.make(T::LeftParen)`, and ends with `_` for anything
it doesn’t recognise.

<Callout kind="pitfall">
`_` is convenient and dangerous. It covers every case you haven’t
written, *including ones added later*. Add a variant to `Op` and a match
with `_ => {}` keeps compiling, quietly doing nothing for it. Use `_` when
“everything else” truly means one answer, as in `is_falsey`, and list
the variants when each one deserves a thought.
</Callout>

<Callout kind="definition">
A **pattern** describes a shape a value can have: literals, enum
variants, names that **bind** parts of the value, the wildcard `_`,
alternatives `p | q`, and tuples of patterns. A binding is a new
variable that exists only inside its arm.
</Callout>

<Callout kind="engine" label="Under the hood">
The heart of the Rust Drip VM is one `match` in `run`, in
`companion/rust/src/vm.rs`, and it reads like your TypeScript switch:

```rust
match op {
    OpCode::Nil => self.push(Value::Nil),
    OpCode::Add => self.add()?,
    OpCode::Negate => { /* ... */ }
    // ...one arm per opcode
}
```

The real one lists all 37 opcodes and has no `_` arm, so adding an
opcode breaks the build until the VM handles it. `OpCode` is marked
`#[repr(u8)]`, which makes each variant exactly the byte that encodes it,
numbered to match the TypeScript VM’s `OP` table.

Underneath, every enum value has a **discriminant**: an integer that
says which variant it holds. The compiler is free to store it in a
smaller type, or to tell variants apart some other way<Cite id="rustref-enum" />.
Either way, it is chapter 78’s tag and payload, and you never write the
tag by hand.

Enums also make bad states impossible to build. Chapter 86’s upvalues
are open (pointing at a stack slot) or closed (holding the value
itself). The Rust VM says exactly that, `enum ObjUpvalue { Open(usize),
Closed(Value) }`, so a closed upvalue that still has a slot can’t exist.
Closing one replaces the whole value: `ObjUpvalue::Closed(...)`.
</Callout>

## What you learned

- An **enum** is one of a fixed set of **variants**, which can carry
  data. It is a discriminated union built into the language.
- **`match`** tries its arms in order and runs the first that fits. It
  is an expression, and it must be **exhaustive**.
- **Patterns** are shapes: literals, variants, bindings, `_`, `|` and
  tuples. Bindings pull the payload out.
- A wildcard covers cases you haven’t thought of yet. Prefer listing
  variants when each needs its own answer.
- The Rust VM’s dispatch loop is a single exhaustive `match` on
  `OpCode`.
