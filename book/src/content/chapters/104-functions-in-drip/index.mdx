## The same work, written out every time

Drip can choose and repeat now, and it can keep lists; however, every
piece of work still has to be written out in full at the place it is
used. Here is a program that prints the areas of two rooms:

```
let w = 3;
let h = 4;
print "area: " + str(w * h);
w = 5;
h = 2;
print "area: " + str(w * h);
```

It works (it prints `area: 12` and then `area: 10`), but the idea
"multiply, turn the answer into a string, print it with a label" is
written twice, glued to whatever `w` and `h` happen to hold. The chapter
*Functions: naming a piece of work* cured this in JavaScript, and Drip
gets the same cure now:

```
fn area(w, h) {
  print "area: " + str(w * h);
}
area(3, 4);
area(5, 2);
```

Two new pieces of syntax arrive together. `fn area(w, h) { ... }` is a
**function declaration**, which the parser turns into a node holding the
name, the parameter tokens and the list of statements in the body.
`area(3, 4)` is a **call expression**: in the Pratt table from the
parsing chapters, `(` is an infix operator that binds as tightly as `.`
and `[`, so whatever expression sits on its left becomes the **callee**,
the thing being called, and `f(1)(2)` parses fine (it calls whatever
`f(1)` gives back).

## A function is a value

Running a `fn` declaration does not run the body; it only makes a value
and gives it a name. Here is the whole case in the companion's
`interpreter.ts`:

```ts
case 'fn':
  this.env.define(s.fn.name.lexeme,
    new DripFunction(s.fn, this.env,
      false));
  return NORMAL;
```

A `DripFunction` holds two things: the declaration node (so the
interpreter can find the parameters and the body later) and the
environment that was current when the declaration ran, which it calls
its `closure` (the chapter *Closures in Drip* is all about why it keeps
that). The `false` says "this is not a class's `init`", which only
matters once classes arrive, and `NORMAL` says the statement finished in
the ordinary way (the completion values of "Choosing and repeating: if,
while and for"). After that, `area` is a variable like any other, holding a
function value: you can copy it with `let g = area;`, put it in a list,
or pass it to another function, and `print area;` shows `fn area`.

Drip also has a second way to make the same kind of value, with no name
at all: an **anonymous function**, written `fn (params) { body }` in the
middle of an expression. The parser makes the same declaration node,
with its name left empty, and the interpreter wraps it in a
`DripFunction` in exactly the same way; `print` shows it as plain `fn`.

<Analogy title="a saved route in a maps app">
Planning a route from home to the station and pressing "save" does not
move you an inch; it stores the directions under a name. Later, each
time you tap "station", the app starts a fresh trip that follows those
directions from wherever the trip begins.
<span slot="breaks">A saved route is followed the same way every time;
a function's parameters let each call start from different values, and
a Drip function always runs to the end of its steps (or to a
`return`), with no chance to reroute half-way.</span>
</Analogy>

## Which values can be called

Now look at the call expression from the interpreter's side. It
evaluates the callee, then the arguments, left to right, and only then
asks what kind of value the callee turned out to be:

```ts
const callee = this.evaluate(e.callee);
const args = e.args.map(
  (a) => this.evaluate(a));
if (callee instanceof DripFunction)
  return this.callFunction(
    callee, args, e.paren);
if (callee instanceof NativeFunction) {
  // check the arity, then run it
}
if (callee instanceof DripClass)
  throw new RuntimeError(e.paren,
    `cannot call a class: use ` +
    `'new ${callee.name}(...)'`);
throw new RuntimeError(e.paren,
  `cannot call ${describe(callee)}`);
```

`e.paren` is the `(` token, kept so that an error can say which line the
call was on, and `describe` names a value with its article (`a number`,
`a list`, `none`), so `3(1)` stops with `cannot call a number`. (The real
`call` has one more branch, for method calls such as `p.step(1)`, which
evaluate their arguments before the method is looked up; the classes
chapter shows why that order matters.)

<Callout kind="definition">
A **callable** is a runtime value that a call expression can run. In
Drip there are two kinds: a **Drip function** (a `DripFunction`, made by
`fn`, named or anonymous) and a **native function** (a
`NativeFunction`, written in TypeScript, such as `len` or `clock`; the
next chapter looks at these closely). Every other value is not callable: calling a number,
a string, a list or `none` is the runtime error `cannot call a number`
(with the right article and type), and calling a class is
`cannot call a class: use 'new Point(...)'`, because Drip makes
instances with `new`, never with a bare call.
</Callout>


## Running the body

Here is what `callFunction` does with a Drip function, with three pieces
of bookkeeping left out (a check on the number of arguments, which the
next chapter is about; the handling of `return`; and a record kept for
error messages; the two chapters after that show them):

```ts
const env = new Environment(f.closure);
const ps = f.decl.params;
for (let i = 0; i < ps.length; i++)
  env.define(ps[i].lexeme, args[i]);
const c = this.executeBlock(
  f.decl.body, env);
```

Line 1 makes a brand-new environment whose parent is the function's
stored `closure`. Lines 2 to 4 walk the parameters, defining each one in
the new environment and giving it the argument in the same position (the
first argument goes to the first parameter, and so on). The last line
runs the body's statements with that environment as the current one,
through the same `executeBlock` you wrote for blocks in the chapter
*Environments and scope*, which switches back to the caller's
environment when the body is done. Step through two calls:

Because every call makes its own environment, two calls never share
their parameters or their local variables, which is exactly what
recursion needs: each call of a recursive function gets its own `n`.
Notice too which environment is the parent: the one where the function
was *written*, not the one it is called from. That is lexical scope,
from the chapter *Scope: where a name can be seen*, and this program
shows it (it prints `global`, because `show`'s calls hang off the
globals, where `show` was declared, and never see the block's `x`):

```
fn show() { print x; }
let x = "global";
{
  let x = "local";
  show();   # global
}
```

## What you learned

- Running `fn` does not run the body: it makes a function value holding
  the declaration and its environment, and defines the name; an
  anonymous `fn (x) { ... }` makes the same kind of value with no name.
- A **callable** is a value a call can run: a Drip function or a native
  function. Calling anything else is a runtime error, and a class must
  be made with `new`.
- A call evaluates the callee, then the arguments, left to right, and
  only then looks at what the callee is.
- Calling a Drip function makes a fresh environment whose parent is the
  function's own, defines the parameters there and runs the body in it.
