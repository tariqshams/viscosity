## A heap that would only grow

Every object the VM makes is linked onto one list, the **object list**
(*Heap objects and lists in the VM*), by `allocate` in `heap.ts`:

```ts
private allocate<T extends Obj>(o: T): T {
  this.bytesAllocated += SIZE[o.type];
  if (this.stress ||
      this.bytesAllocated > this.nextGC)
    this.collect();
  o.next = this.objects;
  this.objects = o;
  return o;
}
```

The last lines link the new object onto the list; the `if` is the
subject of this chapter. Run this:

<Run id="garbage" />

Every pass makes a two-element list that nothing can reach once the pass
ends, yet the object list still links it; without a collector the VM
would keep all 100,000 of them. You may wonder why this
matters, since JavaScript collects its own garbage; the catch is that V8
frees an object only when nothing refers to it, and the object list
refers to *every* object. Only the VM knows which of them Drip code can
still use, so it needs a collector of its own, over its own heap.

## Reachable from the roots

<Analogy title="balloons on strings">
Picture every object as a balloon, tied to other balloons with string,
and a few balloons tied to your wrist. Anything connected to your wrist,
however long the chain, stays; cut the rest loose and they drift away,
including two balloons tied only to each other.
<span slot="breaks">Balloons drift away on their own; garbage sits
there, taking memory, until the collector comes round and finds it.</span>
</Analogy>

A Drip program can only get at an object by starting from something it
holds directly (a stack value, a global, a running function) and
following references; those starting points are the **roots**:

<Figure caption="The VM's roots, and what they reach." takeaway="An object is live if some chain of references leads to it from a root; everything else is garbage, even objects that point at each other.">
  <RootsFigure />
</Figure>

<Callout kind="definition">
**Garbage collection** is reclaiming memory that a program can never
use again. A tracing collector decides what that is by reachability:
the **roots** are the references the program holds directly, and an
object is **live** if some chain of references leads to it from a root.
Every other object is **garbage**, even if other garbage refers to it.
</Callout>

In the companion VM the roots are listed by `markRoots` in `vm.ts`
(wrapped):

```ts
for (let i = 0; i < this.sp; i++)
  mark(this.stack[i]);
for (const f of this.frames)
  mark(f.closure);
for (let u = this.openUpvalues; u;
     u = u.nextOpen) mark(u);
this.globals.forEach((k, v) => {
  mark(k); mark(v);
});
mark(this.initString);
```

<Examples of="garbage-collection roots">

```text
fn f() {
  let a = [];
  let b = [a];
  push(a, b);   # each holds the other
}
f();   # after the call, both are garbage
```

</Examples>

While `f` runs, `a` and `b` sit in stack slots below `sp`, so the first
loop reaches both. Once `f` returns, `sp` drops below their slots (what
is above `sp` is left-overs no code will read), nothing else leads to
them, and both are garbage even though each refers to the other.

<More title="More: why each of the other roots is there">

A running frame's closure owns the constants being used; open upvalues
sit on a list the next capture will search; globals can be read by name
at any time, so both the name strings and the values are marked; and
`initString` is the interned `"init"` that every `new` looks up.
`Heap.collect` adds the functions the compiler is still building and
`extraRoots`, a small stack filled by `heap.push(v)` for a value that is
briefly reachable from nowhere else.

</More>

<Formal title="Live objects">

```text
Live = the smallest set L such that
  every root r is in L, and
  if o is in L and o → p, p is in L
```

<span slot="read">The live objects are the smallest collection that
contains every root and is closed under following references: whenever
o is live and refers to p, p is live too. "Smallest" is what leaves out
two objects that only refer to each other.</span>
</Formal>

## A missing root, caught

An object the VM holds only in a TypeScript variable is not a root, and
is invisible to the collector; forgetting this is the classic collector
bug, and it hides well. Here is a broken variant of `defineNative`:

<MissingRootSteps client:visible />

Run normally, that variant works, because collections are rare. So the
heap has a **stress mode**, `new VM({ stressGC: true })`, which collects
on *every* allocation and **poisons** each freed object (makes reading
it throw). With the broken `defineNative`, `print len([1, 2]);` prints
`2` normally and, under stress mode, throws `use after free: a string
object was collected while still in use`. The real `defineNative`
pushes each new object onto the value stack (a root) as soon as it
exists.

## Marking with a grey stack

The obvious way to find every live object is recursion: mark an object,
then everything it refers to, and so on. However, a Drip program can
build a chain as long as it likes (`head = [i, head]` in a loop, 200,000
times), and a recursive marker would make one host call per link and
overflow JavaScript's own call stack. So the collector keeps its own
pile of work in an array called `gray`:

```ts
private markObject(o: Obj | null) {
  if (!o || o.isMarked) return;
  o.isMarked = true;
  this.gray.push(o);
}
```

The early return means nothing is traced twice, even in a cycle. Then `collect` pops grey objects one at a time
and **blackens** each one, marking everything it refers to (a list's
items, a closure's function and upvalues, an instance's class and
fields, and so on).

<GcSteps client:visible />

<Callout kind="definition">
**Tri-colour marking** sorts objects into three sets while marking.
**White**: not reached yet. **Grey**: reached (marked) but its
references not yet traced; in the companion, the objects on the `gray`
stack. **Black**: reached and fully traced. Marking makes the roots
grey, then blackens grey objects one at a time, greying every white
object they refer to, and ends when nothing is grey. The invariant that
makes this correct: no black object ever refers to a white one, so when
nothing is grey, whatever is still white is unreachable.
</Callout>

<Examples of="tricolor">

```text
let a = [];
push(a, a);   # a list that holds itself
```

</Examples>

The global `a` greys the list; blackening it marks its one item, the
list itself, which is already marked, so marking stops there with the
list black and alive.

## Sweeping, a weak table, and when to collect

With marking done, **sweep** walks the object list once: marked objects
stay and are reset to white, and unmarked ones are unlinked, so V8 can
reclaim them. The string table of *String interning and globals by
name* needs care: as a root it would keep every string alive, and an
entry for a freed string would let `copyString` hand out a dead one. So
it is **weak**: `strings.removeWhite()` drops entries for unmarked
strings. Finally, `allocate` collects only once `bytesAllocated` passes
`nextGC`, which each sweep sets to twice what survived (at least 1 MiB),
so a large live heap is not re-marked over and over.

<Callout kind="definition">
**Mark-sweep** collection has two phases. **Mark** finds every object
reachable from the roots. **Sweep** visits every allocated object (here
by walking the object list) and frees the unmarked ones, resetting the
marked ones for next time. A **weak** table's entries are removed, after
marking, when their keys are unmarked.
</Callout>

<Examples of="mark-sweep">

```text
collect():
  1. mark the roots (grey)
  2. blacken until nothing is grey
  3. strings.removeWhite()
  4. sweep the object list
  then nextGC = max(1 MiB, 2 × survivors)
```

</Examples>

That is the whole of `Heap.collect`, in order: step 3 comes after
marking, so the table knows which strings are live, and before sweeping,
so it never points at a freed one.

<Prompts ids={['weak-strings']} />

<More title="More: V8's marker, a realistic chain, and the reason for extraRoots">

V8 marks with the same three colours, kept as mark bits, and a marking
worklist plays the part of the grey stack; because it marks *while
JavaScript runs*, it also needs a write barrier, so that a black object
cannot gain a reference to a white one behind the marker's
back<Cite id="v8-concurrent-marking" />, and it compacts fragmented
pages after sweeping<Cite id="v8-trash-talk" />. The deep dives *V8’s
garbage collector* and *Incremental and concurrent collection* go there;
the companion stops the program while it collects, so it needs no
barrier.

```text
class Box { init(f) { self.f = f; } }
let b = new Box(fn () { return 1; });
```

The global `b` greys the instance; blackening the instance greys its
class `Box` and the closure in field `f`; the closure greys its
function, and the function greys its constants, until the pile is
empty. Inside `copyString`, the new string is pushed on `extraRoots`
until it is in the string table: nothing between those lines allocates
today, so it is a precaution keeping the rule "a new object is reachable
before anything else can allocate" true if the table ever changes.
