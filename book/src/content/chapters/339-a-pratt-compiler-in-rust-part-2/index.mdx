## Closures that share

The TypeScript compiler from *One pass from source to bytecode* is one
function, `compile`, which keeps its state in local variables; every
helper is a closure written inside it, reading and writing those
variables freely. From `vm/compiler.ts` (trimmed):

```ts
let current: VmToken = { type: 'eof', ... };
let previous: VmToken = current;
let panicMode = false;
function advance() {
  previous = current;
  // ...scan the next token
}
```

Dozens of helpers share those few variables and call each other, even
in a circle: `expression` calls `parsePrecedence`, which calls `infix`,
which calls `parsePrecedence` again. Try the smallest piece of that in
Rust, two closures over one counter:

```rust
let mut pos = 0;
let mut advance = || pos += 1;
let peek = || pos;
advance();
```

rustc 1.97 refuses (trimmed):

```text
error[E0502]: cannot borrow `pos` as
  immutable because it is also
  borrowed as mutable
3 | let mut advance = || pos += 1;
  |                   -- mutable borrow
4 | let peek = || pos;
  |            ^^ immutable borrow
```

A closure that changes a variable holds a mutable borrow of it for as
long as the closure may still be called (the chapter *Iterators and
closures in Rust* showed why<Cite id="klabnik2026" />), and while
that borrow lasts nobody else may even read the variable. The pattern
the whole TypeScript compiler is built on is ruled out.

<Analogy title="one workbench, handed along">
Picture a workshop with one bench, holding all the tools and the
half-built piece. Rather than everyone reaching across at once, the
bench is handed from worker to worker: whoever has it may use anything
on it, and asking a colleague for help means handing the whole bench
over and waiting until it comes back.
<span slot="breaks">Workers can cheat and grab; in Rust the hand-over
is proved at compile time, so nobody can touch the bench while it is
lent out, and it always comes back when the helper returns.</span>
</Analogy>

## The state becomes a struct

So drip-rs gathers the variables into one struct, from
`src/compiler.rs` (comments trimmed, rewrapped):

```rust
struct Compiler<'src, 'a> {
    scanner: Scanner<'src>,
    current: Token<'src>,
    previous: Token<'src>,
    panic_mode: bool,
    block_depth: usize,
    syntax_errors: Vec<String>,
    static_errors: Vec<String>,
    functions: Vec<FunctionState<'src>>,
    classes: Vec<ClassState>,
    heap: &'a mut Heap,
    roots: &'a dyn Trace,
}
```

Every helper is a method taking `&mut self`. A method that calls
another lends it the same `&mut`, and gets it back when the call
returns; there is only ever one user at a time, so there is nothing to
conflict with. The two lifetimes (the chapter *Lifetimes*) say what the
compiler borrows. `'src` is the source text: a `Token<'src>` holds its
lexeme as a slice of the source, so tokens are small `Copy` values that
never copy text, and local variable names are slices too. `'a` is what
the caller lends: its `Heap`, where functions and strings are allocated,
and `roots`, the caller's own garbage-collection roots, as a trait
object (`&dyn Trace`). `compile` builds the `Compiler` on its own
stack, and when it returns the struct is dropped, which ends both
borrows.

In a family with one TV remote, whoever holds it decides what is on; if

<span slot="breaks">A sister may keep the remote all evening; a Rust

<Callout kind="definition">
**Threading compiler state through `&mut self`** means putting all of
a compiler's changeable state in one struct and writing every parse and
emit helper as a method on `&mut self`. Each call lends the whole state
to the callee for the length of the call. It replaces closures over
shared variables, which the borrow checker does not allow.
</Callout>

<Formal title="Lending the compiler">

```text
caller: &mut c ──call g(c)──▶ g: &mut c
caller: (frozen)              g works
caller: &mut c ◀──returns──── g ends
```

<span slot="read">The caller holds the only mutable borrow of the
compiler c. Calling g lends that borrow to g, and while g runs the
caller is frozen: it cannot touch c. When g returns, the borrow comes
back to the caller.</span>
</Formal>

## A stack instead of a linked list

When `fn` bodies nest, the TypeScript compiler links one `FnCompiler`
per function through an `enclosing` field, and resolving a captured
variable walks that list, changing entries on the way, which in Rust
would mean holding mutable borrows of several of them at once. drip-rs
keeps the functions in a `Vec`, innermost last (from `compiler.rs`):

```rust
fn state(&mut self)
    -> &mut FunctionState<'src> {
    self.functions.last_mut()
        .expect("compiling a function")
}

fn chunk(&mut self) -> &mut Chunk {
    &mut self.state().chunk
}
```

A function is named by its index, its **level**: `resolve_upvalue(level,
name)` looks in `self.functions[level - 1]` and recurses with the level
below, and a level is a plain number that borrows nothing. Classes nest
the same way, in `classes: Vec<ClassState>`. Notice also that each
`FunctionState` has its own `chunk`, where TypeScript writes straight
into the heap object's chunk; `end_function` moves the finished chunk
into the heap as an `Rc<Chunk>`, frozen from then on.

## Read first, then borrow

One habit shows up all over `compiler.rs`. Here are two ways to emit a
byte tagged with the current line:

<Examples of="compiler-state">

```rust
fn emit(&mut self, byte: u8) {
    self.chunk().write(byte,
        self.previous.line);
}
// error[E0503]: cannot use
//   `self.previous.line` because it
//   was mutably borrowed
```

```rust
fn emit(&mut self, byte: u8) {
    let line = self.previous.line;
    self.emit_at(line, byte);
}
```

```text
return 1;      # line 1: a static rule
print ;        # line 2: a syntax error
line 2: expected an expression,
  found ';'
```

</Examples>

The first is a natural attempt, and it fails: `self.chunk()` returns a
`&mut Chunk` that borrows *all* of `self` (the method's signature says
so), and that borrow lasts until `write` is done, so reading
`self.previous.line` for the argument falls inside it. The second is
drip-rs's real `emit`: it reads the line into a local first, a cheap
copy of a `usize`, and only then borrows. The third shows two more
fields at work. `return` at the top level breaks a static rule, which
goes into `static_errors`; `print ;` is a syntax error, which goes into
`syntax_errors` and sets `panic_mode` until the next statement (as in
*Syntax errors and recovery*). At the end, `compile` keeps only one
list:

```rust
let (function, _) = compiler.end_function();
if compiler.syntax_errors.is_empty() {
    errors.append(
        &mut compiler.static_errors);
} else {
    errors.append(
        &mut compiler.syntax_errors);
}
errors.is_empty().then_some(function)
```

With a syntax error, the static rules are never reported, so the
program above prints only line 2's error (both VMs agree); delete the
`print ;` line and you get `line 1: 'return' outside a function`
instead. `then_some` turns `true` into `Some(function)` and `false` into
`None`, where TypeScript returned `null`.

<Callout kind="engine" label="Under the hood">
At run time a `&mut` is an address, so every method receives one
pointer to the compiler's state, which is no dearer than the closures
of the TypeScript version. The struct also does a job for the garbage
collector, because functions still being compiled must stay alive.
Before allocating, the compiler runs
`self.heap.collect(&[self.roots, &self.functions])`, and
`FunctionState` implements `Trace`, marking its function and the
constants in its chunk.
</Callout>

## What you learned

- Closures that share changeable variables, the TypeScript compiler's
  style, do not pass the borrow checker: a closure that writes a
  variable borrows it mutably for as long as it may be called.
- **Compiler state** lives in one `Compiler` struct, and every helper is
  a method on `&mut self`; a call lends the whole state, and it comes
  back on return.
- `'src` lets tokens and names borrow the source; `'a` covers the
  caller's heap and roots.
- Nested functions are a `Vec<FunctionState>`, innermost last, named by
  level, rather than an `enclosing` list.
- Read what you need into a local *before* calling a `&mut self` helper
  such as `chunk()` (E0503).
