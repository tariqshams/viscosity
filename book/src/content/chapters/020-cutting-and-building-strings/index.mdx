## Cutting out a word

Last chapter's scanner can notice that, in `'width = 42;'`, a run of
digits starts at index 8 and stops just before index 10; however, the
rest of the interpreter wants the piece `'42'` as a string of its own. And when the scanner meets a character it
does not understand, it should say so in a sentence, such as
"Unexpected '#' at index 3", which has to be built out of pieces too.
Strings come with ready-made **methods** (functions you call with a dot,
as in chapter 14) for exactly this.

<Analogy title="cutting a ribbon at marked points">
Lay a ribbon along a ruler and cut it at the 8 mark and the 10 mark; the
piece in your hand is everything between the two cuts. `slice(8, 10)`
cuts a string the same way, at numbered points *between* the
characters.
<span slot="breaks">Scissors use the ribbon up; `slice` copies the piece
and leaves the original string exactly as it was, because strings never
change.</span>
</Analogy>

<Figure takeaway="slice cuts between characters." caption="Picture numbered fences between the characters, 0 before the first and 11 after the last. slice(8, 10) cuts at fences 8 and 10, so it copies indexes 8 and 9, and never index 10.">
  <SliceRuler />
</Figure>

```js
const s = 'let x = 42;';

s.slice(0, 3);       // 'let'
s.slice(8, 10);      // '42'
s.slice(8);          // '42;'
s.slice(-3);         // '42;'
```

`slice(start, end)` copies the characters from index `start` up to,
**but not including**, `end`, so `slice(0, 3)` is indexes 0, 1 and 2,
`'let'`. With the fence picture, the length of the piece is always
`end - start`. Leaving `end` out means "to the end", and a negative number
counts back from the end, so `slice(-3)` is the last three characters.

Here is the scanner doing it for real, cutting `'42+7'` into pieces: the
finger `i` moves over a run of digits, and `slice` copies the run.

<Callout kind="definition">
The **string methods** you will use most<Cite id="mdn-string" />:
`slice(start, end)` copies a piece (`end` not included);
`includes(x)` and `startsWith(x)` answer `true` or `false`;
`split(sep)` cuts a string at every copy of `sep` into an array of
strings; and the array method `join(sep)` glues an array back into one
string, with `sep` between the pieces. None of them change the original
string: they return new values.
</Callout>

<Formal title="What slice copies">

```text
s.slice(a, b) = s[a] s[a+1] … s[b−1]
length of the piece = b − a
```

<span slot="read">slice from a to b is the characters at index a, a plus
one, and so on up to b minus one, written side by side; there are b minus
a of them. (This holds for a and b between 0 and the length, with a no
bigger than b.)</span>
</Formal>

<Examples of="string-methods">

```js
'scanner'.slice(1, 4); // 'can'
'scanner'.slice(4);    // 'ner'
```

```js
const s = 'let x = 42;';
s.includes('42');     // true
s.startsWith('var');  // false
```

```js
const src = 'let a = 1;\nprint a;';
const lines = src.split('\n');
lines.length; // 2
lines[1];     // 'print a;'
['a', 'b', 'c'].join(' + '); // 'a + b + c'
```

<Run id="string-tools" />

</Examples>

The first cuts `'can'` out of the middle (indexes 1, 2 and 3), then
everything from index 4 on. The second searches: `includes` asks whether
`'42'` appears anywhere, and `startsWith` whether the string begins with
`'var'` (it begins with `'let'`). The third is realistic: `'\n'` is the
**newline** character, the invisible character at the end of each line,
so splitting a program at it gives an array of its lines, which is how an
interpreter can show you the line an error is on; `join` goes the other
way, gluing pieces with a separator between them.

A common slip is to call a method and expect the string to change:

```js
const s = 'abc';
s.toUpperCase();       // result thrown away
console.log(s);        // abc
const u = s.toUpperCase();
console.log(u);        // ABC
```

`toUpperCase` returns a new string in capitals; the first call's result
was never stored, and `s` cannot change, so it still prints `abc`.

## Template literals

Gluing a sentence together with `+` gets messy fast:
`"Unexpected '" + c + "' at " + i` is hard to read and easy to get
wrong. A **template literal** is a string written between backticks,
where `${...}` drops in the value of any expression<Cite id="mdn-template-literals" />:

```js
const c = '#';
const i = 3;
const a = "Unexpected '" + c + "' at " + i;
const b = `Unexpected '${c}' at ${i}`;
a === b; // true
```

Both make `Unexpected '#' at 3`; in the template literal the text is
written as it will appear, and each `${...}` is replaced by the value
inside it.

<Analogy title="a form letter">
A form letter says "Dear ____, your order of ____ has shipped", and the
office fills in each blank before posting it. A template literal is the
letter, and each `${...}` is a blank.
<span slot="breaks">An office fills blanks with names and numbers from a
list; a template literal's blank can hold any calculation at all,
`${2 + 3}` or `${xs.length}`, worked out at the moment the string is
made.</span>
</Analogy>

<Callout kind="definition">
A **template literal** is a string in backticks, `` `...` ``, where
`${expr}` is replaced by the value of `expr`, turned into a string. It
may also run over several lines.
</Callout>

<Examples of="template-literal">

```js
`${2 + 3} cats`; // '5 cats'
```

```js
const name = 'x';
const xs = [1, 2, 3];
`${name} has ${xs.length} items`;
// 'x has 3 items'
```

```js
function err(line, msg) {
  return `[line ${line}] Error: ${msg}`;
}
err(3, 'Expect ";"');
// '[line 3] Error: Expect ";"'
```

</Examples>

The first works out `2 + 3` inside the blank; the second drops in a
variable and a property; the third is the shape of the error
messages your interpreter will print in Part III. Spot the difference in
the quotes:

```js
'Hi ${name}'; // 'Hi ${name}', as typed
`Hi ${name}`; // 'Hi x'
```

Only backticks fill in `${...}`; inside ordinary quotes it is plain text.

## Building a string piece by piece

When you do not know in advance how long a string will be, build it in a
loop: start with the empty string `''`, and add to it.

```js
function bar(n) {
  let out = '';
  for (let i = 0; i < n; i++) {
    out += '#';
  }
  return out;
}

console.log(`[${bar(3)}]`); // [###]
```

`out` starts empty. `out += '#'` is short for `out = out + '#'`, so after
three passes it is `'###'`, and the template literal wraps it in square
brackets. Because strings are immutable, each `+=` makes a new, longer
string and points `out` at it; the old one is simply dropped.

<Analogy title="threading beads">
You make a necklace by threading one bead after another onto a string,
and when you stop, you tie it off. Building a string is the same: one
piece at a time, in order, then `return` it.
<span slot="breaks">A real necklace grows in place; each `+=` actually
makes a whole new string with one more bead, and lets the old one
go.</span>
</Analogy>

<Callout kind="definition">
**Building a string** means starting from `''` and adding pieces, either
with `+=`, or by `push`ing the pieces into an array and calling
`join('')` once at the end.
</Callout>

<Examples of="string-building">

```js
let s = '';
s += 'a';
s += 'b';
s; // 'ab'
```

```js
const parts = [];
parts.push('x');
parts.push('=');
parts.push('1');
parts.join(' '); // 'x = 1'
```

```js
function pad(s, n) {
  let out = s;
  while (out.length < n) out = ' ' + out;
  return out;
}
pad('42', 5); // '   42'
```

</Examples>

The first adds twice to an empty string. The second collects the pieces
in an array and glues them once with `join`, separator included. The third is
realistic: in chapter 102 you will print bytecode in neat columns, and
`pad` adds spaces *in front* (`' ' + out`) until the string is `n`
characters wide, using a `while` loop from chapter 10, so `'42'` becomes
`'   42'`.

<OtherLanguages>

```js
const s = 'let x = 42';
s.slice(8, 10);        // '42'
s.split(' ');          // 4 words
['a', 'b'].join('-');  // 'a-b'
`x is ${42}`;
```

```python
s = 'let x = 42'
s[8:10]                # '42'
s.split(' ')           # 4 words
'-'.join(['a', 'b'])   # 'a-b'
f'x is {42}'
```

```java
String s = "let x = 42";
s.substring(8, 10);    // "42"
s.split(" ");          // 4 words
String.join("-", "a", "b");
"x is " + 42;
```

```c
char out[16];
snprintf(out, sizeof out,
         "x is %d", 42);
/* no slice, split or join
   built in: you write them */
```

</OtherLanguages>

Python cuts with `s[8:10]`, the same as `slice(8, 10)`; its `join` is
called on the *separator*, the other way round from JavaScript; and its
template literals are **f-strings**, with `{}` instead of `${}`. Java's
`substring` matches `slice`, but its `split` treats the separator as a
search *pattern*, so some characters (such as `.`) mean something
special. C has none of these built in, apart from `snprintf`, which fills
in a format string much like a template literal.

keeps exactly one copy of each distinct string, so checking whether two
names are equal becomes a single identity check (the `===` on references
from chapter 7) instead of a comparison character by character.
</Callout>

## What you learned

- **String methods** `slice`, `includes`, `startsWith` and `split`, with
  the array method `join`, cut, search and glue strings; they return new
  values and never change the original.
- `slice(start, end)` stops just before `end`, so the piece has
  `end - start` characters.
- **Template literals**, in backticks, drop values into a string with
  `${...}`.
- **String building** grows a result piece by piece, with `+=` or with
  an array and `join`.
