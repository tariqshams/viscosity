## A calculator with no memory

Last chapter's evaluator can work out `(1 + 2) * 3`. Then it forgets.
It can't keep a running total, it can't name an intermediate result,
and it can't even show you an answer unless something prints it. Real
programs *do* things, and they remember. In Drip, the parts that do
things are statements.

## A program is a list

The parser does not return one tree. It returns an array of them, one
per statement, in the order they were written. Running the program is
a loop over that array, from `interpret` in
`companion/ts/src/interpreter.ts`:

```ts
interpret(statements: Stmt[]) {
  for (const s of statements) execute(s);
}
```

<Callout kind="intuition">
A program is a recipe: a numbered list of steps, followed in order.
Step 4 can use the onion you chopped in step 2, but not one you will
only chop in step 6. And if step 5 goes wrong, you stop there: steps 1
to 4 really happened, and steps 6 and 7 never will.
</Callout>

<Callout kind="definition">
In Drip, a **program is a list of statements**. The interpreter runs
them one at a time, top to bottom. Each statement runs to completion
before the next starts, and a runtime error stops the list where it is.
</Callout>

## Statements make things happen

Here are the three statements of this chapter, simplified from
`execute`:

```ts
function execute(s: Stmt): void {
  switch (s.kind) {
    case 'expression':
      evaluate(s.expression); // dropped
      return;
    case 'print': {
      const v = evaluate(s.expression);
      out(stringify(v));
      return;
    }
    case 'let':
      globals.define(s.name.lexeme,
        s.initializer
          ? evaluate(s.initializer) : null);
      return;
  }
}
```

Look at the return type: `void`. `evaluate` hands back a value, but
`execute` hands back nothing. A statement is only worth running for
what it *changes*. `print` changes the world outside the program: a new
line of output. `let` changes the program's memory: a new variable. An
expression statement evaluates its expression and drops the value, so
`1 + 2;` is legal Drip that does nothing you can see. It is there for
expressions that change something as they are evaluated, like an
assignment.

<Callout kind="definition">
A **side effect** is a change that running code makes to the world,
beyond producing a value: printing output, or creating or changing a
variable. Statements exist for their side effects. An **expression
statement** evaluates an expression only for its side effects, and
discards the value.
</Callout>

## A table of globals

Where does `let` put the variable? For now, in one table of names and
values that the whole program shares. Simplified from the
`Environment` class in `runtime.ts`:

```ts
class Globals {
  values = new Map<string, Value>();
  define(name: string, v: Value) {
    this.values.set(name, v);
  }
  get(name: Token): Value {
    const k = name.lexeme;
    if (this.values.has(k))
      return this.values.get(k)!;
    throw new RuntimeError(name,
      `Undefined variable '${k}'.`);
  }
  // assign: the same check, then set
}
```

Using a variable is a lookup, and assigning one is a lookup followed by
an overwrite:

```ts
case 'variable':
  return globals.get(e.name);
case 'assign': {
  const value = evaluate(e.value);
  globals.assign(e.name, value);
  return value;
}
```

Notice that the assignment *returns* the value. Assignment is an
expression with a side effect, which is why `print a = 3;` prints `3`
and `let b = a = 5;` sets both. Step through a small program and watch
the table and the output change:

<Callout kind="definition">
A **global variable** is one declared at the top level of the program,
outside any block. It lives in a single table shared by the whole
program, from the moment its `let` runs until the program ends. In
Drip, `let` always defines (even a name that already exists), while
assignment and use require the name to exist already.
</Callout>

Because the table is filled in as the program runs, *when* matters.
`print a; let a = 1;` fails with `Undefined variable 'a'.`: when the
`print` runs, no `let` has put `a` in the table yet. The parser can't
catch this. It is a runtime error, found only when that line runs.

## A first look at blocks

## What you learned

- A Drip **program is a list of statements**, run in order. A runtime
  error stops the list, and earlier output stays.
- Statements run for their **side effects**: `print` writes output,
  `let` creates a variable. An expression statement drops its value.
- **Global variables** live in one table: `let` defines, a name looks
  up, and assignment overwrites a name that must already exist.
- Assignment is an expression, so it has a value as well as an effect.
- Using a name before its `let` has run is a runtime error.
- A block gets its own table, discarded at the `}`.
