## Two kinds of variable

Here is what drip-rs's disassembler prints for a global, the program
`let n = 1; n = n + 1; print n;` written on three lines:

```text
0000    1 const               0 '1'
0003    | define.global       1 'n'
0006    2 load.global         3 'n'
0009    | const               4 '1'
0012    | add
0013    | store.global        2 'n'
0016    | pop
0017    3 load.global         5 'n'
0020    | print
```

and for two locals in a block, `{ let a = 1; let b = 2; print a + b; }`
on five lines:

```text
0000    2 const               0 '1'
0003    3 const               1 '2'
0006    4 load.local          1
0008    | load.local          2
0010    | add
0011    | print
0012    5 pop
0013    | pop
```

(Each listing's closing `none`, `return` is left off.) The TypeScript
VM prints both byte for byte the same, as *Globals by name* and *Locals
as stack slots* built them. The global is looked up by its name every
time; the locals are bare slot numbers, 1 and 2, and their names appear
nowhere.

<Analogy title="a hotel register and a theatre ticket">
At a hotel, reception finds you by looking your name up in the
register every time; at a theatre, your ticket says row F, seat 12, and
you walk straight there. Globals are hotel guests; locals hold theatre
tickets.
<span slot="breaks">A theatre prints its seat numbers once, for good; a
local's slot is worked out by the compiler for each function, and the
same slot is handed to a different local once a block has ended.</span>
</Analogy>

## Globals: names in a table

A global's name goes into the constant pool as an interned string; in
`src/compiler.rs`, `identifier_constant(name)` is two lines,
`let s = self.intern(name);` and
`self.make_constant(Value::String(s))`. It does not look for an earlier
copy, which is why the first listing has four constants that are all
`'n'` (the same `StrRef` four times). The VM keeps the globals in
`globals: Table`, a field of the `Vm`, and three arms of the dispatch
loop use it (rewrapped, comments left out):

```rust
OpCode::DefineGlobal => {
    let name = self.read_string();
    self.globals.set(name, self.peek(0));
    self.pop();
}
OpCode::StoreGlobal => {
    let name = self.read_string();
    if self.globals
        .set(name, self.peek(0))
    {
        self.globals.delete(name);
        // "undefined variable 'm'"
    }
}
```

`define.global` overwrites happily, which is why a second `let` of the
same global is allowed. `store.global` uses `set`'s return value: `true`
means the name was new, a mistake for an assignment, so it deletes the
entry again and reports `undefined variable 'm'`. `load.global` gets an
`Option` from `self.globals.get(name)` where TypeScript got `undefined`.
The globals table is also a garbage-collection root, beside the stack.

## Locals: a Vec the compiler keeps

Locals never reach a table: the compiler works out each one's stack
slot while it compiles, so at run time a local is an index. The
TypeScript compiler records a `name: string`, a `depth: number` (with
`-1` while the initialiser is compiled) and `isCaptured` for each local;
drip-rs records:

```rust
struct Local<'src> {
    name: &'src str,
    depth: Option<usize>,
    is_captured: bool,
}
```

`name` is a slice of the source, borrowed for `'src` (*A Pratt
compiler in Rust, part 2*), so no name is copied; and `depth` is `None`
where TypeScript used `-1`, so the compiler cannot forget to check,
because there is no number to compare until the `Option` is
opened<Cite id="rust-std-option" />.

<Analogy extra title="a seating plan drawn before the lesson">
A teacher draws a seating plan before class, one name per desk; during
the lesson she just says "desk two, please", and the plan goes in the
bin when term ends.
<span slot="breaks">Pupils move desks when they like; a local's slot
never changes while its block runs, and the compiler's plan is thrown
away when the function is finished, not at the end of term.</span>
</Analogy>

Resolving a name searches the locals from the end, so the innermost
variable with that name, the one that shadows the others, wins (from
`compiler.rs`, rewrapped, the message's `format!` shortened):

```rust
fn resolve_local(&mut self, level: usize,
    name: Token<'src>) -> Option<usize> {
    let locals =
        &self.functions[level].locals;
    let (slot, local) = locals.iter()
        .enumerate().rev()
        .find(|(_, l)|
            l.name == name.lexeme)?;
    if local.depth.is_none() {
        // static error: "cannot read 'a'
        // in its own initialiser"
    }
    Some(slot)
}
```

The `?` (from *Option and Result*) returns `None` when no local has
the name, and `named_variable`
then tries a captured variable, and finally a global. Reporting the
error needs `&mut self`, which is allowed because `local` is not used
after `is_none()`: the borrow of `self.functions` has already ended.

<Callout kind="definition">
**Compile-time locals in drip-rs** are a `Vec<Local>` in each
`FunctionState`. A local's index in that `Vec` is its stack slot (slot
0 is reserved for the function being run, or `self` in a method). Each
`Local` holds its name as a `&str` into the source, its scope depth as
`Option<usize>` (`None` until initialised), and whether a closure
captures it. Declaring a local emits nothing: its initialiser's value is
already in the right slot.
</Callout>

<Formal title="Which slot a name means">

```text
slot(x) = max { i | locals[i].name = x }
```

<span slot="read">The slot of a name x is the largest index i whose
local is called x: the most recently declared, innermost one. If no
local is called x, there is no slot, and x is looked for further
out.</span>
</Formal>

## Hold the function, lose the compiler

The TypeScript `endScope` keeps the current function in a local and
emits while it loops. Written that way in Rust, keeping
`let state = self.state();` across a call to `self.emit_op(...)`, rustc
1.97 refuses with E0499, "cannot borrow `*self` as mutable more than
once at a time": `state` is a `&mut` into `self.functions`, used
again after the call, and `emit_op` needs all of `self`. drip-rs reads
the one fact it needs, pops, and lets `state` go before it emits (from
`compiler.rs`, rewrapped, comments left out):

```rust
loop {
    let state = self.state();
    let depth = state.scope_depth;
    let captured =
        match state.locals.last() {
        Some(local) if local.depth
            .is_some_and(|d| d > depth) => {
            local.is_captured
        }
        _ => break,
    };
    state.locals.pop();
    self.emit_op(if captured {
        OpCode::CloseUpvalue
    } else { OpCode::Pop });
}
```

`declare_variable` has the same habit: it first computes
`let duplicate = state.locals.iter().rev().take_while(..).any(..);`, a
plain `bool`, and only then reports `'a' is already declared in this
scope`.

The first breaks a static rule: `declare_variable` finds an `a` at the
same depth, and nothing runs (exit code 65); at the top level it would
be fine, as a second `let` of a global replaces it. The second surprises
people: the inner `a` is declared (depth `None`) before its initialiser
is compiled, so `a + 1` finds the unfinished inner `a`, not the global;
`let b = a + 1;` works. The third mixes globals and locals.

<Callout kind="engine" label="Under the hood">
At run time none of this is left. `load.local` adds the frame's base,
`self.slots`, to its operand and reads `self.stack` there: one addition
and one indexed read. `load.global` hashes nothing (the `StrRef` brings
its hash), but it still probes a table. The `Vec<Local>` is dropped with
its `FunctionState` when the function is finished, so local names never
reach the heap at all.
</Callout>

## What you learned

- A **global** is an interned name in the constant pool and an entry in
  the VM's `globals` table; `store.global` on a new name deletes it
  again and reports `undefined variable`.
- **Compile-time locals** are a `Vec<Local<'src>>`: the index is the
  stack slot, the name borrows the source, and `depth: Option<usize>`
  replaces TypeScript's `-1`.
- `resolve_local` searches from the end and uses `?` to fall through to
  captured variables and globals.
- Don't hold `self.state()` across a call that needs `&mut self`: read
  what you need into a local, finish with the borrow, then **emit or
  report** (E0499 otherwise).
