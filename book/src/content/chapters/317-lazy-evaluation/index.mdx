## Work nobody asked for

Here is a function that picks one of two values, called with an
expensive second choice:

```js
function pick(c, a, b) {
  return c ? a : b;
}
pick(true, 1, slow()); // slow() runs
true ? 1 : slow();     // slow() does not
```

JavaScript, like C, Java, Python and Rust, works out every argument
before the call starts, so `slow()` runs and its answer is thrown away;
the built-in `? :` only evaluates the side it picks. A **lazy** language
such as Haskell turns this round for every call: nothing is evaluated
until something needs its value. That lets you write `pick` as an
ordinary function, build a list of every prime number and take the
first ten (chapter 39's lazy sequences, as the default), and skip work
that turns out not to matter. This chapter shows what a compiler builds
to make that happen.

## Thunks: work, wrapped up for later

To delay `slow()` we need a value that *stands for* the work without
doing it, and can do it later. That value is a **thunk**: the code of
the expression plus the variables it uses, packed up and waiting.

<Analogy title="flat-pack furniture">
A flat-pack wardrobe arrives as a box of parts and a sheet of
instructions. It takes no effort to carry the box into the spare room,
and if you never need the wardrobe you never build it; the day you need
somewhere for coats, you open the box and follow the sheet.
<span slot="breaks">Once built, a wardrobe stays built. A plain thunk
does not: forcing it twice does the work twice, unless it is made to
remember, which is the next section.</span>
</Analogy>

<Analogy extra title="an IOU">
An IOU is a promise of money that is cheap to write and easy to pass
around; it only costs anyone anything when it is cashed.
<span slot="breaks">Cashing an IOU can fail, or be refused. Forcing a
thunk runs ordinary code, which always gives the same value in a pure
language, though it may loop forever or throw.</span>
</Analogy>

In JavaScript a thunk is a function of no arguments, and **forcing**
it means calling it. After closure conversion (chapter 298) that is a
heap record holding a code pointer and the expression's free variables;
GHC's runtime lays a thunk out as exactly that, an info pointer to the
code, then the free variables, plus one spare field that will later
point to the value<Cite id="ghc-rts-updates" />.

<Callout kind="definition">
A **thunk** is a suspended computation: a heap value holding the code
of an expression and the free variables that code needs, which runs
the code when its value is first demanded (it is **forced**). Building a
thunk costs one allocation; the expression itself costs nothing until
it is forced.
</Callout>

<Examples of="thunk">

```js
const t = () => slow();  // no work yet
t();                     // the work runs
```

```js
const n = 5;
const t = () => n * n;  // captures n
console.log(t());       // 25
```

```js
// lazy pick: pass thunks, force one
function pick(c, a, b) {
  return c ? a() : b();
}
pick(true, () => 1, () => slow()); // 1
```

</Examples>

The first makes a thunk and forces it. The second shows the "free
variables" half: the thunk captures `n`, as any closure does, so it can
compute `n * n` whenever it is forced. The third is `pick` written by
hand in the style a lazy compiler would produce: every argument becomes
a thunk, and the body forces only the one it chooses, so `slow()` never
runs.

## Three ways to pass an argument

Once arguments can be thunks, there are three classic strategies for
evaluating them, studied side by side by Plotkin in
1975<Cite id="plotkin1975" />. **Call-by-value** evaluates the argument
before the call. **Call-by-name** passes the unevaluated expression and
evaluates it afresh at every use (beta-reduction, chapter 119, does
exactly this: it substitutes the expression itself). **Call-by-need**
passes a thunk too, but the first force *updates* the thunk with its
value, so every later use shares it.

<Run id="strategies" />

`slow` counts its own runs. `twice` uses its argument twice, and always
receives a function to call. By value, `slow()` runs first and `twice`
gets a function that returns the stored `v`: one run. By name, it gets
`() => slow()`, and each use runs it: two runs. By need, `delay` wraps
`slow` in a function that remembers: the first call runs `f` and sets
`done`, the second returns `val`: one run, and zero if `twice` had not
used its argument at all.

<Analogy extra title="the office coffee pot">
The first person who wants coffee in the morning brews a pot; everyone
after pours a cup from it, and if nobody wants coffee, nobody brews.
<span slot="breaks">Coffee goes cold and the pot runs out. A forced
thunk's value never changes and can be read any number of times, which
is safe only because the expression has no side effects that a second
run would have repeated.</span>
</Analogy>

Step through one thunk's life, in the three states GHC's runtime
describes: a thunk, a **black hole** while it is being evaluated, and,
once it is updated, an indirection to its value<Cite id="ghc-rts-updates" />:

<ThunkSteps client:visible />

<Callout kind="definition">
**Call-by-need** (lazy evaluation) passes each argument as a thunk,
evaluates it the first time its value is needed, and then updates the
thunk with that value, so every other use shares the result. It does
the work of call-by-name at most once, and in a pure language it gives
the same answers.
</Callout>

<Formal title="Call-by-need, with a heap">

```text
      Γ : e ⇓ Δ : z
───────────────────────────────
(Γ, x ↦ e) : x ⇓ (Δ, x ↦ z) : z
```

<span slot="read">This is the variable rule of Launchbury's natural
semantics<Cite id="launchbury1993" />. Γ and Δ are heaps (maps from names
to expressions). To evaluate a variable x bound to e: take x's binding
out of the heap, evaluate e in what is left to a value z (the heap may
change to Δ), then put x back bound to z. Taking x out is the black
hole; putting z back is the update.</span>
</Formal>

<Examples of="call-by-need">

```rust
let big = LazyCell::new(|| {
    println!("computing");
    6 * 7
});
println!("before");
println!("{}", *big);
println!("{}", *big);
// prints: before, computing, 42, 42
```

```python
class Doc:
    @cached_property
    def words(self):
        print("counting")
        return 42
# d.words twice: counting, 42, 42
```

```text
thread 'main' panicked at .../lazy.rs:
LazyCell instance has previously
been poisoned
```

</Examples>

The first is Rust's `std::cell::LazyCell`, a value "initialized on the
first access"<Cite id="rust-lazycell" />: run here with rustc 1.97,
"computing" prints once, after "before", and both reads give 42. The
second is Python's `functools.cached_property`, computed once and then
cached for the life of the object<Cite id="python-cached-property" />
(Python 3.13 here prints "counting" once). The third is the black hole
in Rust: `LazyCell` marks itself poisoned while its closure runs (its
source says this "prevents reentrant accesses"), so a closure that reads its own cell panics
with that message, as it did here. GHC reports the same situation as
`<<loop>>`, the `NonTermination` exception, with the honest caveat that
the runtime does not promise to notice every
loop<Cite id="ghc-nontermination" />. JavaScript keeps one small
piece of laziness: the right side of `a && b` (and `||`, `??`) is
evaluated only if it is needed.

## How Haskell makes it fast

In Haskell every argument and every `let` is lazy, so a naive compiler
would allocate a thunk for almost everything. GHC compiles to the STG
machine, an abstract machine "designed to support non-strict
higher-order functional languages" on ordinary
hardware<Cite id="peytonjones1992stg" />, where thunks are closures with
an update step. Most of its speed then comes from *not* making thunks:
when the compiler can prove a value will be needed anyway, it computes
it at once, which is the subject of the next chapter.

## What you learned

- A **thunk** is code plus free variables, run when forced.
- **Call-by-value** runs arguments first; **call-by-name** runs them at
  each use; **call-by-need** runs them at most once and shares.
- Runtimes mark a thunk as a **black hole** while it runs (to catch
  loops) and **update** it with its value afterwards.
