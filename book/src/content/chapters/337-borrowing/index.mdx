## Lending, not giving

The last chapter left you with an awkward rule: pass a `String` to a
function and it moves in, and the caller loses it.

```rust
fn count(s: String) -> usize {
    s.len()
}

fn main() {
    let name = String::from("drip");
    let n = count(name);
    println!("{name} has {n} bytes");
}
```

That fails with E0382, "borrow of moved value: `name`", and rustc's note
even says what to do: "consider changing this parameter type in
function `count` to borrow instead if owning the value isn't necessary".
You could have `count` hand the string back, but every function that
only wants to *look* at a value would then need that round trip.

TypeScript never has this problem: passing an object passes an arrow to
it (*References: two names, one object*), and the caller keeps its own
arrow. Rust can pass an arrow too; it also keeps track of who holds
one.

<Analogy title="lending a friend a book">
You lend a friend a book. They can read it, but it is still yours, and
when they are done it comes back; they do not get to give it away or
throw it out, because it was never theirs to throw.
<span slot="breaks">A friend might keep the book for months; a Rust
borrow is checked by the compiler to end before the owner is finished
with the value, so the book always comes back in time.</span>
</Analogy>

Put a `&` in front of the parameter's type and in front of the argument:

```rust
fn count(s: &String) -> usize {
    s.len()
}

let n = count(&name);
println!("{name} has {n} bytes");
```

Now `name` is still usable after the call. `&name` makes a **reference**
to the string without moving it, and when `s` goes away at the end of
`count`, nothing is dropped, because `s` never owned
anything<Cite id="rust-book-borrowing" />. Forget the `&` at the call and
rustc says "expected `&String`, found `String`", with the help line
"consider borrowing here: `&name`".

<Callout kind="definition">
A **reference** `&T` is an address you can follow to a value of type `T`
that someone else owns. Making one is called **borrowing**. The owner
keeps ownership, so when a reference goes out of scope the value is not
dropped, and Rust guarantees that a reference always points at a valid
value<Cite id="rust-book-borrowing" />.
</Callout>

## Borrowing to change something

A plain `&` lets the borrower read, never write. To change a borrowed
value you need a **mutable reference**, `&mut`, and `*` to follow it to
the value:

```rust
fn bump(n: &mut i32) {
    *n += 1;
}

let mut hits = 0;
bump(&mut hits);
bump(&mut hits); // hits is now 2
```

Step through both kinds of loan, across a call:

<RefSteps client:visible />

`*n` follows the reference to the number it points at (method calls like
`s.len()` follow it for you, so you rarely write `*` there). Notice how
loud this is. The owner says `let mut`, the caller says `&mut hits`, and
the parameter says `&mut i32`; in TypeScript, any function you passed an
object to could quietly change it, while in Rust you can see it at the
call.

<Analogy title="a museum and its restorer">
Visitors to a museum may look at a painting as long as they like, but
not touch it: that is a shared borrow. The restorer is given the key to
the case and may change the painting, but still does not own it and
cannot sell it: that is a mutable borrow. Only the museum, the owner,
can lend the painting out or get rid of it.
<span slot="breaks">A museum lets visitors in while the restorer works;
Rust does not, as the next chapter's rule explains.</span>
</Analogy>

Every cross in that table is a compile error you will meet. Here they
are, each broken line next to the fixed one:

```rust
fn bump(n: &i32) { *n += 1; }     // broken
fn bump(n: &mut i32) { *n += 1; } // fixed

let hits = 0; bump(&mut hits);     // broken
let mut hits = 0; bump(&mut hits); // fixed
```

```text
error[E0594]: cannot assign to `*n`,
  which is behind a `&` reference
  `n` is a `&` reference, so it cannot be
  written to
error[E0596]: cannot borrow `hits` as
  mutable, as it is not declared as mutable
```

The first writes through a shared reference; the help line suggests
`&mut i32`. The second lends something for changing whose owner never
said it could change. (Leave out the `*`, writing `n += 1`, and the
error is E0368: "`+=` cannot be applied to type `&mut i32`", with a hint
to dereference.)

<Examples of="borrow">

```rust
fn count(s: &String) -> usize {
    s.len()
}
let name = String::from("drip");
println!("{}", count(&name)); // 4
println!("{name}");           // still ours
```

```rust
fn reset(v: &mut i32) {
    *v = 0;
}
let mut score = 41;
reset(&mut score);
println!("{score}"); // 0
```

The first lends `name` to `count`, which reads its length, 4, and gives
it back unchanged, so `name` can be printed afterwards. The second lends
`score` for changing; `*v = 0` writes 0 into `main`'s variable through
the reference, so it prints `0`. The runnable one is the program from

<OtherLanguages title="Let a function change the caller's number">

```rust
fn bump(n: &mut i32) { *n += 1; }
let mut hits = 0;
bump(&mut hits); // hits is 1
```

```ts
function bump(box: { n: number }) {
  box.n += 1;
}
const hits = { n: 0 };
bump(hits); // hits.n is 1
```

```c
void bump(int *n) { *n += 1; }
int hits = 0;
bump(&hits); /* hits is 1 */
```

```python
def bump(box):
    box[0] += 1
hits = [0]
bump(hits)  # hits[0] is 1
```

</OtherLanguages>

C's version is Rust's almost character for character: `&hits` takes the
address and `*n` follows it. The differences: TypeScript and Python
cannot lend a plain number at all, so you wrap it in an object or a list
and lend that, and then *any* call can change it without the call site
saying so; C lets you pass `&hits` freely, with no check that the
address is still valid or that nobody else is writing; and Rust marks
the permission to change in the type, at both ends.

<Callout kind="definition">
A **shared reference** `&T` can only read. A **mutable reference**
`&mut T` can read and write, and is made with `&mut x` from a variable
declared `let mut`. The **dereference** operator `*r` gives the value a
reference points at. No reference can move or drop the value it
borrows.
</Callout>

<Formal title="Typing a borrow">

```text
    Γ ⊢ x : T          Γ ⊢ x : T  x is mut
──────────────     ──────────────────
 Γ ⊢ &x : &T        Γ ⊢ &mut x : &mut T

 Γ ⊢ r : &T   (or &mut T)
──────────────────────────
       Γ ⊢ *r : T
```

<span slot="read">If x has type T, then &x has type "reference to T". If
x has type T and was declared mut, then &mut x has type "mutable
reference to T". And if r is either kind of reference to a T, then *r
(following it) has type T. Writing through *r is allowed only when r is
a &mut.</span>
</Formal>

## What you learned

- A **reference** `&T` lets you use a value without owning it. Making
  one is **borrowing**, and dropping a reference never drops the value.
- A **mutable reference** `&mut T` can change the value, through `*r`.
  It needs `let mut` on the owner, `&mut` at the call and `&mut` in the
  parameter type.
- Owners may read, change, move and drop; shared borrowers may only
  read; mutable borrowers may read and change, but never move or drop.
