## Four numbers that belong together

A particle has a position and a velocity, four numbers; in a tuple,
`let p = (0.0, 0.0, 3.0, 4.0);`, nothing says which is which, and `p.2`
means "the third one". TypeScript gives every part a name; Rust does
too, with one difference that runs through this chapter: you declare the
shape first, and every value is built from it.

<Analogy title="a printed form">
A passport application is printed with labelled boxes: surname, date of
birth, place of birth. Every copy has the same boxes in the same places,
the office will not accept one with a box missing, and you cannot add a
box of your own in the margin. The printed blank form is the **struct
definition**; each filled-in copy is one **value** of the struct.
<span slot="breaks">A paper form can be photocopied, so two people can
hold the same answers; a Rust struct value has one owner, and handing it
over moves it (as *Ownership: moves, copies and clones* showed for
strings) unless the type says it may be copied.</span>
</Analogy>

## Structs

```rust
struct Particle {
    x: f64,
    y: f64,
    vx: f64,
    vy: f64,
}
```

`struct Particle` names a new type, and the braces list its **fields**,
each with a name and a type; this defines no value yet, only the shape.
Step through one particle's life:

<FieldSteps client:visible />

<Examples of="struct">

```rust
struct Point { x: f64, y: f64 }
let (x, y) = (5.0, 6.0);
let a = Point { x, y };
let mut b = Point { y: 0.0, ..a };
b.x += 1.0;
println!("{} {}", b.x, b.y); // 6 0
```

</Examples>

`Point { x, y }` is **field init shorthand** (`x` alone means `x: x`).
`Point { y: 0.0, ..a }` is **struct update syntax**: give the fields
that differ, then `..a` takes the rest from `a`, so `b` starts as `5, 0`.
Writing `b.x` needs `let mut b`, because mutability belongs to the
binding, never to one field; and a struct expression must give every
field, so `Point { x: 1.0 }` is E0063, "missing field `y` in initializer
of `Point`"<Cite id="rust-book-structs" />. A struct moves like a
`String`, and a function that only reads one borrows it, `p: &Point`.
(Rust also has tuple structs, `struct Meters(f64);`, read with `m.0`,
which make a plain number a type of its own.)

It looks like a TypeScript interface, but an interface is erased before
the program runs and the engine must discover each object's shape for
itself; a struct *is* the type at run time, and the compiler knows its
size and the place of every field. Rust's default layout may reorder a
struct's fields, but it promises that an array of `T` puts element `n`
exactly `n × size_of::<T>()` bytes from the
start<Cite id="rustref-type-layout" />:

<Figure takeaway="Rust stores structs inline; JavaScript stores references to objects." caption="On this machine a Particle is 32 bytes (four 8-byte f64s), and [Particle; 1000] is exactly 32,000 bytes. A JavaScript array of particle objects holds references, and each object lives somewhere else.">
  <InlineArray />
</Figure>

There is no pointer to chase from one particle to the next, which is
what made arrays of objects slow in *Prefetching, pointer chasing,
branches and SIMD*.

<Callout kind="definition">
A **struct** is a named record type: a fixed list of **fields**, each
with a name and a type. A **struct expression**, `Name { field: value,
... }`, builds a value of it and must give every field. `value.field`
reads one field; writing to a field needs the whole value to be bound
with `let mut`<Cite id="rust-book-structs" />.
</Callout>

## impl blocks

A TypeScript class keeps fields and methods in one block. Rust splits
them: the `struct` holds the data, and an **`impl` block** attaches
functions to the type.

<Examples of="impl">

```rust
impl Particle {
    fn new(vx: f64, vy: f64) -> Self {
        Particle { x: 0.0, y: 0.0, vx, vy }
    }
    fn speed(&self) -> f64 {
        (self.vx * self.vx
            + self.vy * self.vy).sqrt()
    }
}
let p = Particle::new(3.0, 4.0);
println!("{}", p.speed()); // 5
```

</Examples>

`new` has no `self` parameter, so it is called on the type, with two
colons: Rust has no constructors and no `new` keyword, and `new` is
only the usual name for a function that builds a
value<Cite id="rust-book-methods" />. Inside the block, **`Self`** names
the type. `speed` takes `self` first, the value it is called on, so it
is a **method**, called with a dot, and works out √(3² + 4²) = 5. Call
`new` with a dot by mistake and rustc says E0599, "this is an associated
function, not a method", with "use associated function syntax".

<Callout kind="definition">
An **`impl` block**, `impl Type { ... }`, attaches functions to a type.
All of them are **associated functions**; those whose first parameter is
`self` are also **methods**, called as `value.method(...)`, and the
others are called as `Type::function(...)`. Inside the block, **`Self`**
names the type being implemented.
</Callout>

## Three kinds of self

JavaScript's `this` is whatever you called the method on, and the method
may read it, change it or keep it. Rust's `self` is an ordinary
parameter, so its type says which of those the method does:

<ReceiverSteps client:visible />

**`&self`** borrows the value to read it, as most methods do; **`&mut
self`** borrows it to change it, so the caller's variable needs `let
mut` (or the call is E0596); and **`self`** takes ownership, so the
value moves in and the caller cannot use it afterwards (E0382, with
"`Particle::stopped` takes ownership of the receiver `self`")
<Cite id="rust-book-methods" />.

<Examples of="self-receiver">

```rust
// from companion/rust/src/vm.rs
fn push(&mut self, value: Value)
fn pop(&mut self) -> Value
fn peek(&self, distance: usize) -> Value
```

<Run id="particle-o342" />

</Examples>

The Rust Drip VM's stack: `push` and `pop` change it, so they borrow it
mutably, while `peek`, which reads the value `distance` slots below the
top, only looks; you can tell which methods change the VM from their
first line. The runnable one has all three receivers: `speed` reads,
`step` moves the particle, and `stopped` consumes it and returns a new
one. Notice `Particle::step(&mut p, 1.0)`: when Rust looks up a method,
it borrows the receiver to match its `self`<Cite id="rustref-method-call" />,
so `p.step(1.0)` *is* that call, which is why the borrowing rules apply
to method calls although you never write the `&`.

<Figure takeaway="A method call is an ordinary call with the borrow filled in." caption="Rust adds &, &mut or nothing to match the method's receiver, which is why the borrowing rules apply to method calls although no & is written.">
  <CallSugar />
</Figure>

<Callout kind="definition">
The **self receiver** is a method's first parameter. **`&self`** (short
for `self: &Self`) borrows the value shared, **`&mut self`** borrows it
mutably, and **`self`** takes ownership of it. `v.m(a)` means
`T::m(&v, a)`, `T::m(&mut v, a)` or `T::m(v, a)` to match.
</Callout>

<More title="More: a struct with a borrowed reader, products, and the class version">

<Run id="particle" />

That is the struct with a free function, `speed(&p)`, and with
`#[derive(Debug)]`, which asks the compiler to write the code that
`{:?}` prints with (*Traits, trait objects and derive* explains
`derive`). A struct is a **product** of its fields: a struct of two
`bool`s has 2 × 2 = 4 possible values; *Enums, match and patterns*
builds the other kind, a value that is one thing *or* another.

```ts
class Particle {
  x = 0; y = 0;
  constructor(
    public vx: number,
    public vy: number,
  ) {}
  step(dt: number) {
    this.x += this.vx * dt;
  }
}
```

In the TypeScript, `this` is there without being asked for and any
method may change it, so nothing says that `step` changes the particle;
the Rust `step` must ask for `&mut self`, which makes the caller write
`let mut p`. *Memory layout in Rust* measures struct layouts with
`size_of`, and *Struct of arrays in Rust, measured* turns an array of
`Particle`s into one column per field.

</More>

<Analogy extra title="handing over your car">
A friend who borrows your car for a ride can look but not change
anything; a mechanic borrows it to work on it, and gives it back changed;
a buyer takes it for good, and you never drive it again. That is `&self`,
`&mut self` and `self`, in that order.
<span slot="breaks">A real mechanic might keep the car for a week while
you take the bus; a `&mut self` borrow lasts only for the one call, and
the value is yours again the moment the method returns.</span>
</Analogy>

## What you learned

- A **struct** is a named record built with every field and stored
  inline; an **`impl`** block gives it associated functions and methods.
- The **receiver** says what a method does: `&self` reads, `&mut self`
  changes, `self` takes; Rust adds the borrow at the call.
