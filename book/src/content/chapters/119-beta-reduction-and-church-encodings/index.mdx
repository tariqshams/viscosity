## One rule to run everything

The last chapter wrote terms down and substituted into them, but nothing
*ran*: `(λx. x) a` sat there, unchanged. The lambda calculus has exactly one
rule of computation, and it is the one every function call you have
ever written follows: to apply a function to an argument, take its body
and put the argument where the parameter was.

<Formal title="Beta-reduction">

```text
(λx. t) s  →  [x ↦ s] t
```

<span slot="read">A function with parameter x and body t, applied to an
argument s, steps to (the arrow is read "reduces to") the body t with s
substituted for x, using the careful, capture-avoiding substitution of
the last chapter.</span>
</Formal>

<Analogy title="a mail merge">
A form letter says "Dear ______, your order has shipped"; merging it
with a name fills every blank with that name and leaves a finished
letter.
<span slot="breaks">A merged letter is finished; the result of a beta
step is often a new term with more functions applied to more arguments
in it, so the merging carries on, sometimes for ever.</span>
</Analogy>

<Callout kind="definition">
A **redex** (short for *reducible expression*) is a function applied to
an argument, `(λx. t) s`. **Beta-reduction** replaces a redex, anywhere
inside a term, by `[x ↦ s] t`. A term with no redex left is in **normal
form**: it is the term's answer<Cite id="church1941" />.
</Callout>

<Examples of="beta-reduction">

```text
(λx. x) a  →  a
```

```text
(λx. λy. x) a b
→ (λy. a) b
→ a
```

```text
succ 1
→ λf. λx. f ((λf. λx. f x) f x)
→ λf. λx. f ((λx. f x) x)
→ λf. λx. f (f x)          the numeral 2
```

</Examples>

<BetaSteps client:visible />

The first is the identity doing its job, in one step. The second picks
the first of two arguments: application groups to the left, so the
redex is `(λx. λy. x) a`, which leaves `λy. a`, a function that
ignores its argument; one more step gives `a`. The third, which you can
step through below, is the realistic one: `succ` applied to the numeral 1 really
does compute the numeral 2, in three steps, using nothing but
substitution.

## Which redex first?

A term can hold several redexes at once, so we must choose. Some terms
never reach a normal form at all: `Ω = (λx. x x) (λx. x x)` reduces,
in one step, to itself. (The good news, a theorem of Church and Rosser,
is that a term can never reach two *different* normal forms: the
choices can only change whether, and how fast, you get there.)

<Analogy title="unpacking the shopping">
You can put every bag away the moment you get home, or leave them by the
door and open one only when you need something from it.
<span slot="breaks">A bag opened late is opened once; in the plain
"only when needed" strategy, an argument used twice is worked out twice,
which is why lazy languages remember the result the first time.</span>
</Analogy>

- **Normal order** reduces the leftmost, outermost redex first, even
  inside a λ body. If a normal form exists, it finds
  it<Cite id="pierce2002" />.
- **Call by value** reduces an argument to a value before the call, and
  never reduces inside a λ body. JavaScript and Drip both work this
  way.
- **Call by name** passes the argument unevaluated, like normal order,
  but also never reduces inside a λ body.

<Figure takeaway="The same term can finish under one strategy and run for ever under another." caption="(λx. z) Ω never uses its argument. Normal order applies the function first and is done; call by value insists on finishing Ω first, and never does.">
  <StrategyFork />
</Figure>

Here is the right-hand side of that picture in JavaScript, next to the
cure:

```js
const loop = () => loop();
((x) => 'z')(loop());
// RangeError: Maximum call stack
// size exceeded
((x) => 'z')(() => loop()); // 'z'
```

The first call works out its argument before calling, so `loop()` runs,
calls itself until the call stack runs out, and the program stops with
that exact error. The second passes a function that *would* run `loop`,
which the callee never calls: wrapping an argument in a function is how
a call-by-value language delays work it may not need.

## Booleans and numbers from functions

Without `true`, `false` or numbers, how can anything useful be
computed? By choosing functions that *behave* like them. A boolean is a
choice between two things, so let it be a function that takes two
things and keeps one:

<Formal title="Church booleans and numerals">

```text
true  = λt. λf. t
false = λt. λf. f
if    = λb. λx. λy. b x y
0     = λf. λx. x
2     = λf. λx. f (f x)
succ  = λn. λf. λx. f (n f x)
plus  = λm. λn. λf. λx. m f (n f x)
```

<span slot="read">true takes two arguments and keeps the first; false
keeps the second; so if b then x else y is b applied to x and y.
The numeral n takes a function f and a start x and applies f to x n
times. succ applies f once more than n does; plus applies f m times on
top of n times.</span>
</Formal>

These are **Church encodings**, after the numerals Church used. In the
runnable example they become arrow functions, and to read a numeral out
we hand it "add one" and `0`. Try `plus(two)(three)`:

<Run id="church" />

Recursion needs a name to call, and lambda terms have no names, but a
term can still call itself. `Y = λf. (λx. f (x x)) (λx. f (x x))`
has the property that `Y g` reduces to `g` applied to (something equal
to) `Y g`, so `g` receives itself as an argument. Under call by value
it runs for ever, like `Ω`; the variant used in call-by-value languages wraps
`x x` in a function, `λv. x x v`, to delay it, and the last lines of
the runnable example use it to compute 5 factorial with no named
recursion at all.

## What you learned

- **Beta-reduction**, `(λx. t) s → [x ↦ s] t`, is the lambda
  calculus's only rule; a term with no redex is in **normal form**.
- **Normal order** finds a normal form whenever one exists; **call by
  value**, which JavaScript and Drip use, may loop where it would not.
- Functions can play booleans, numbers and recursion: the **Church
  encodings** and `Y`.
