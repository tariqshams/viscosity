## Who decides to collect?

The TypeScript heap of *Reclaiming memory: mark and sweep* collects from
inside `allocate`: it finds the roots through `heap.vm`, the compiler's
functions, and an `extraRoots` stack that protects a half-built value.
drip-rs cannot do that, because the heap is a field of the VM and
cannot borrow the VM back. So whoever allocates decides, from `vm.rs`
(rewrapped):

```rust
fn alloc<T: HeapObject>(
    &mut self, object: T) -> Gc<T> {
    self.collect_if_needed();
    self.heap.alloc(object)
}

fn collect_if_needed(&mut self) {
    if self.heap.should_collect() {
        self.collect_garbage();
    }
}
```

`Heap::alloc` itself never collects. `should_collect()` is true once the
bytes allocated pass `next_gc`, or always in stress mode, and
`collect_garbage` builds the VM's roots and calls `heap.collect`. The
price is one rule, written in the comment on `Vm::alloc`: anything the
new object refers to must already be reachable from a root, because the
new object itself is not yet. That is the argument the chapter
*Capturing variables in Rust* made for closures.

## Roots are trait objects

Anything that can report the handles it holds implements one trait, from
`gc.rs`, and the collector takes its roots as a slice of trait
objects<Cite id="rust-reference-trait-object" />:

```rust
pub trait Trace {
    fn trace(&self, marks: &mut Marks);
}

pub fn collect(&mut self,
               roots: &[&dyn Trace])
```

There are impls for `Gc<T>`, `StrRef`, `Value` (an arm per object kind,
none for `none`, booleans and numbers), `Table`, `Option<T>`, `[T]` and
`Vec<T>`, so `self.stack.trace(marks)` marks a whole stack. `dyn` is
needed because one call can mix types: the VM passes `&[&roots]`, a
`VmRoots` of borrowed fields (the stack, the frames, the globals, the
open upvalues and the interned `"init"`); the compiler passes
`&[self.roots, &self.functions]`, whatever the VM gave it plus its own
half-built functions (*A Pratt compiler in Rust, part 2*); and
`--disassemble`, with no VM at all, passes `&()`.

## Mark bits outside the objects

TypeScript objects have an `isMarked` field. Put a mark bit in each
object of a Rust arena, and marking what an object refers to fails
(rustc 1.97, on a toy, trimmed):

```text
error[E0502]: cannot borrow `*self` as
  mutable because it is also borrowed
  as immutable
6  | for &r in &self.nodes[i].refs {
   |           ------------------- immutable
7  |     self.mark(r); // sets a bit
   |     ^^^^^^^^^^^^ mutable borrow
```

Tracing reads objects; marking writes bits; with both in one struct,
the two borrows overlap. So drip-rs keeps the bits in a separate
`Marks` value, one `Vec<bool>` per arena plus the grey stack, and lifts
it out of the heap while it works. From `Heap::collect` (comments
trimmed):

```rust
let mut marks =
    std::mem::take(&mut self.marks);
marks.reset(self);
for root in roots {                  // 1.
    root.trace(&mut marks);
}
while let Some(object) = marks.gray.pop() {
    self.blacken(object, &mut marks); // 2.
}
self.interned.retain_keys(           // 3.
    |s| marks.strings[s.handle.index()]);
self.sweep(&marks);                  // 4.
self.marks = marks;
```

`mem::take` swaps an empty `Marks` in and hands back the real
one<Cite id="rust-std-mem-take" />, so `blacken(&self, object, &mut marks)`
borrows the heap shared and the bitmap mutably: two separate values.
`reset` sizes every bit vector to its arena and clears it, so each
collection starts fresh and sweep never has to unmark survivors (the
TypeScript sweep does). Step 3 is the weak string table: entries for
unmarked strings are dropped before the strings themselves are freed.
The grey stack holds a `Gray`, an enum with one variant per kind of
object that can refer to others; strings and natives refer to nothing,
so marking one turns it black at once.

<Callout kind="definition">
drip-rs's **arena GC** is mark and sweep over one arena per object type.
Marking fills a bitmap kept outside the objects (a `Vec<bool>` per
arena, cleared at the start of every collection), starting from roots
passed in as `&dyn Trace`. Sweeping visits every slot, frees each live
one whose bit is false, and pushes its index on that arena's **free
list**, which `Arena::insert` pops before growing the arena.
</Callout>

<Formal title="What survives a collection">

```text
R₀ = roots
Rₖ₊₁ = Rₖ ∪ { p | o ∈ Rₖ, o → p }
live = R, the first Rₖ with Rₖ₊₁ = Rₖ
freed = slots − live
```

<span slot="read">Start with the set of objects the roots name. Each
round, add every object that something already in the set refers to.
When a round adds nothing, the set is everything reachable, and that is
what survives; every other live slot is freed. The grey stack is the
round still to be done: the objects added but not yet looked inside.</span>
</Formal>

## Sweep, free lists and stress

Sweep runs the same loop over all nine arenas (stamped out by a small
`macro_rules!`), freeing with `Arena::remove(i, reuse)`: the slot is
`take`n, so it becomes `None` and the object is dropped (with its
`Box<str>`, its tables or its `Vec`s), and if `reuse` is true the index
goes on the arena's free list. The TypeScript sweep unlinks the object
from its list instead. Pacing is the same in both VMs: subtract what was
freed, then set `next_gc` to twice what is left, but at least 1 MiB.

A missing root is the classic collector bug, and it hides: it bites only
if a collection runs at exactly the wrong moment. **Stress mode** makes
every moment that moment: `should_collect()` is always true, and it also
sets `poison_freed`, so `reuse` is false and no slot is handed out
again. A stale handle then finds `None` and panics with "use after free"
instead of quietly reading whatever object moved in, which does the job
of the TypeScript heap's poisoning. `tests/stress_gc.rs` runs the 165
corpus programs in ten folders (closures, classes, inheritance, strings,
functions, lists, methods, fields, for and programs) this way.

<Callout kind="engine" label="Under the hood">
A `Vec<bool>` spends a byte per mark bit, since `bool` is one
byte<Cite id="rust-std-size-of" />, where a packed bitset would need an
eighth of that; and `reset` and `sweep` visit every slot, freed ones
too, where the TypeScript sweep walks only its list of allocated
objects. In exchange the bitmap is a plain value the borrow checker can
see is separate from the heap, and a slot index is enough to find any
object's bit. Both are choices a later optimisation could revisit.
</Callout>

## What you learned

- In drip-rs, **allocation never collects** by itself: the VM or the
  compiler asks `should_collect()` and calls `collect` with its roots,
  so a new object's references must already be reachable.
- Roots are **`&dyn Trace`** values: the VM's borrowed fields, the
  compiler's functions, or `()`.
- **Mark bits live in a separate bitmap**, taken out of the heap with
  `mem::take`, so tracing (reads) and marking (writes) never borrow the
  same thing.
- **Sweep** frees unmarked slots onto per-arena **free lists**; **stress
  mode** collects before every allocation and never reuses a slot, so a
  missing root panics at once.
