## A counter that won't count

Here is the first loop counter anyone writes, in Rust:

```rust
fn main() {
    let x = 5;
    x = 6;
    println!("{x}");
}
```

In TypeScript, `let x = 5; x = 6;` is fine. rustc 1.97 refuses (its
messages in this book are real, wrapped to fit your screen):

```
error[E0384]: cannot assign twice to
  immutable variable `x`
 --> e2.rs:3:5
  |
2 |     let x = 5;
  |         - first assignment to `x`
3 |     x = 6;
  |     ^^^^^ cannot assign twice to
  |           immutable variable
  |
help: consider making this binding mutable
  |
2 |     let mut x = 5;
  |         +++
```

(`{x}` inside the string prints the variable `x`.) The fix is in the
`help:` line, and it tells you the whole first idea of this chapter.

<Callout kind="intuition">
In Rust, every variable is a box that locks itself as soon as you put
something in it. If you know a box's contents will change, you ask for
an unlocked one up front. The word you write is `mut`, and anyone
reading the code sees at a glance which boxes change.
</Callout>

## let and let mut

Step through it:

<BindingSteps client:visible />

The mapping from TypeScript is short:

```
// TypeScript       // Rust
const x = 5;        let x = 5;
let y = 5;          let mut y = 5;
```

Rust makes the safe choice the short one. Most variables never change,
and the compiler can then promise you that they don't.

<Callout kind="definition">
`let` binds a name to a value. Without `mut` the binding is
**immutable**: assigning to it again is a compile error. `let mut` makes
it **mutable**. A new `let` with an existing name **shadows** the old
variable: it makes a new variable, which can even have a new type.
</Callout>

One difference from `const` matters a lot. In chapter 7, `const`
froze only the arrow: you could still `push` onto a `const` array. In
Rust, an immutable binding covers the value too:

```rust
let xs = vec![1, 2];
xs.push(3);
```

```
error[E0596]: cannot borrow `xs` as
  mutable, as it is not declared as mutable
```

`vec![1, 2]` makes a growable array, a `Vec` (chapter 228). "Borrow" is
chapter 223's word. For now read it as: changing `xs` needs `let mut
xs`. (Chapter 235 meets the few types that bend this rule.)

## Constants

Rust also has `const`, for values fixed before the program runs. The
type is required, and the name is in capitals. Here is one from
drip-rs's compiler:

```rust
const UINT8_COUNT: usize = 256;
```

That's the limit you met in chapter 95: one byte can name only 256
constants or locals. A `const` may be declared outside every function,
and is usable anywhere in its scope<Cite id="klabnik2026" />.

## One number becomes many

TypeScript has one `number`, and it is always a 64-bit float (chapter
51). V8 quietly stores small integers as Smis when it can, but that's
the engine's choice, not yours. Rust makes you choose:

<Figure takeaway="Rust's number types say how many bytes a value takes." caption="Sizes on a 64-bit machine, from std::mem::size_of with rustc 1.97. usize matches the machine's pointer width.">
  <TypeWidths />
</Figure>

- **Signed integers** `i8`, `i16`, `i32`, `i64`, `i128` hold negative
  and positive whole numbers. **Unsigned** `u8` to `u128` hold zero and
  up. The number is the width in bits.
- **`usize`** is unsigned and as wide as an address. Indexes and lengths
  use it.
- **`f64`** is exactly JavaScript's number. `f32` is half the size.
- **`bool`** is `true` or `false`. **`char`** is one Unicode scalar
  value in four bytes, written in single quotes: `'é'`. That's not a
  JavaScript string index, which gives a UTF-16 code unit (chapter 19).

You rarely write types on `let`. Rust infers them, and falls back to
`i32` for whole numbers and `f64` for decimals<Cite id="klabnik2026" />:

```rust
let n = 5;        // i32
let f = 2.5;      // f64
let b: u8 = 255;  // annotated
let i: usize = 3;
```

<Callout kind="definition">
The **scalar types** hold a single value: the integers `i8` to `i128`
and `u8` to `u128`, plus `isize` and `usize`, the floats `f32` and
`f64`, `bool` and `char`. Integer literals default to `i32` and
decimals to `f64`.
</Callout>

## No silent conversions

Adding an `i32` to an `f64` is an error:

```
error[E0277]: cannot add `f64` to `i32`
 --> e4.rs:4:22
  |
4 |     println!("{}", a + b);
  |                      ^ no implementation
  |                        for `i32 + f64`
```

You convert with `as`, and you say exactly where:

```rust
let a: i32 = 7;
let b: f64 = 2.0;
println!("{}", a as f64 / b); // 3.5
println!("{}", a / 2);        // 3
```

That last line is a trap for TypeScript hands. **Dividing two integers
gives an integer**, cut toward zero: `7 / 2` is `3`, and `-7 / 2` is
`-3`. `as` can lose information too: `3.9_f64 as i32` is `3`, and an
`i32` holding `300` becomes `44` as a `u8`.

What about a `u8` holding 255, plus one? In a debug build the program
stops with a panic, `attempt to add with overflow`. In a release build
it wraps around to 0<Cite id="klabnik2026" />. If you *want* wrapping,
say so: `x.wrapping_add(1)`.

<Callout kind="pitfall">
Never rely on release builds wrapping. Debug builds panic at the same
spot, and the overflow is a bug either way. Use `wrapping_add` and
friends to ask for wrapping on purpose.
</Callout>

## What you learned

- `let` is TypeScript's `const`; **`let mut`** is TypeScript's `let`.
  Immutability covers the whole value, not just the arrow.
- **Shadowing** with a second `let` makes a new variable, possibly of a
  new type. `mut` changes the value in the same variable.
- The **scalar types**: `i32` (default), `u8`, `i64`, `usize` for
  indexes, `f64` (JavaScript's number), `bool`, `char`.
- No silent conversions: use `as`. Integer division truncates. Overflow
  panics in debug builds; `wrapping_add` wraps on purpose.
