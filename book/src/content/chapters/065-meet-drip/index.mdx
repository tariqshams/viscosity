## A language you can hold in your head

JavaScript is a big language, with many years of features piled on top
of each other, and starting there is a poor way to learn how a language
works inside; you would spend months on corners before you reached the
middle. So for Part III you will build a smaller one, this book's own
language, called **Drip**. It is designed to be small enough to
implement completely in a few weeks, and familiar enough that the
JavaScript you already know carries over, while still having the parts
that make real languages hard to build: closures, classes and
inheritance.

<Analogy title="a model kit of a real car">
A good model kit is much smaller than the car, and some comforts are
missing; however, the engine, the wheels and the steering are all there,
and they work the way the real ones do. Once you have built the model,
the real car stops being a mystery.
<span slot="breaks">A model is smaller in every part. Drip is small in
the *number* of features, but each one it has works at full size: its
closures are real closures, and its classes are real classes.</span>
</Analogy>

<Analogy title="a learner's car on quiet roads">
You learn to drive in a small car on quiet streets: the pedals, the
wheel and the mirrors are the same as on any car, so almost everything
you learn carries over, and nothing too fast can happen while you
learn.
<span slot="breaks">A learner's car leaves out nothing a driver needs;
Drip leaves things out on purpose (a big library, for a start), and a
few of those gaps change how an implementation is built.</span>
</Analogy>

## Values and variables

Drip has numbers, strings, `true` and `false`, and `none`, which means
"no value" (like JavaScript's `null`). Variables are made with `let`;
and `print` is a **statement**, a command in the language itself rather
than a function, so it needs no brackets:

<Run id="values" />

Line 1 prints `3.5`: every number is a 64-bit float, as in JavaScript,
so dividing does not round down. Line 2 joins two strings with `+`,
giving `dripdrop`. Line 3 uses `&&` exactly as JavaScript does (and
`||` for "or"), and prints `true`. Line 4 prints `false`, and line 5
prints `none`. Then `let cups = 3;` makes a variable, and
`cups += 1;` adds 1 to it (Drip has `+=` and `-=`, but no `++`), so
`print cups;` shows `4`. The last line prints `0.30000000000000004`,
the same rounding you met in *Floats and typed arrays*, because Drip's
numbers are JavaScript's numbers underneath. Comments start with `#`
and run to the end of the line.

## Deciding and repeating

`if`, `while` and `for` look nearly the way you would expect, with two
small changes: the condition needs no brackets around it, and the body
always takes braces, even when it is one statement (`if x > 1 { ... }`).
One more rule differs from JavaScript, and it is
worth stepping through slowly: which values count as true.

<TruthSteps client:visible />

<Formal title="Drip's truth rule">

```text
truthy(v) = false   if v is none or false
truthy(v) = true    otherwise
```

<span slot="read">To decide an if or a while, Drip asks whether the
value v is truthy. The answer is false in exactly two cases, when v is
none and when v is false, and true for every other value: every number,
zero included, every string, the empty one included, and every
list, function, class and instance.</span>
</Formal>

<Examples of="drip">

```
let cups = 3;
print cups + 1;
```

## Functions and closures

Functions are declared with `fn`, a name, parameters in brackets and a
body in braces. They are values, so a function can return another
function, and the inner one remembers the variables around the place it
was made: a **closure**, exactly as in *Closures: functions that
remember*.

<Run id="functions" />

The first four lines define `square` and print `square(4)`, which is
`16`. Then `makeCounter` makes a local `n` set to 0 and, inside it, a
function `count` that adds 1 to `n` and returns it; `makeCounter`
returns `count` itself (no brackets after it, so it is not called).
`let c = makeCounter();` keeps that function in `c`, and each `c()`
updates the same `n`, printing `1` and then `2`. The last line prints a
function as a value: `fn makeCounter`. Each call to `makeCounter`
makes a new `n`, and the `count` it returns keeps that `n` alive after
the call has finished; making that work inside the interpreter is the
job of the chapter *Closures in Drip*.

## Classes

Drip has classes with methods, `self` (Drip's name for JavaScript's
`this`) and a constructor, which must be called `init`. You make an
instance with `new`, as in JavaScript. A class inherits from another
with `extends`, and `super.name(...)` calls the parent's version of a
method. That is what the third example above does: `Cup` has
`init(ml)`, which stores the amount on the new instance as `self.ml`,
and a method `pour(x)` that takes `x` away and returns what is left.
`Mug extends Cup` inherits both and replaces `pour` with one that first
prints a warning and then calls `super.pour(x)`. So `new Mug(300)` runs
`Cup`'s `init` with `ml` set to 300, `m.pour(50)` prints
`careful, hot` and then `250`, and printing the instance itself shows
its class and fields, `Mug { ml: 250 }`.

## What you learned

- **Drip** is this book's own small language: numbers (64-bit floats),
  strings, booleans, `none`, lists, functions, closures and classes.
- `print` is a statement; comments start with `#`; there is `+=` but no
  `++`; conditions take no brackets and bodies always take braces.
- Only `none` and `false` count as false; `0` and `""` are true.
- Classes use `init` for the constructor, `self` for the instance,
  `extends` to inherit and `super` to reach the parent; instances are
  made with `new`.
