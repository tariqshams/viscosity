## Two garbage collectors deep

Think back to chapter 158. Your Drip VM is a TypeScript program, so it
runs on V8, and V8 has a garbage collector<Cite id="v8-trash-talk" />.
Yet you still had to write a second collector, a mark and sweep over the
VM's own object list, because only the VM knows which Drip objects are
still reachable. Two collectors, stacked.

Then think back to chapter 57. Every JavaScript object carries a hidden
header, and V8 decides how numbers are stored. Viscosity, the compiler
you finished in Part IX, exists because JavaScript gives you no direct
say over memory layout. It has to *trick* the engine into a struct of
arrays, using typed arrays.

Track B starts again in a language where neither trick is needed.

<Callout kind="intuition">
TypeScript is like a hotel. The staff (the engine) clean your room,
decide where your luggage goes, and tidy up after you leave. Rust is
like owning the house. You decide where everything goes, and nobody
cleans up for you, but a very strict inspector checks the plans before
you're allowed to move in.
</Callout>

## What Rust is, and what it costs

**Rust** compiles ahead of time to machine code, has no garbage
collector, and still refuses to compile programs that would read freed
memory (outside code marked `unsafe`, chapter 318)<Cite id="klabnik2026" />. It manages that with a set of
*ownership* rules, checked by the compiler. They are the heart of this
part of the book, and they begin in chapter 301.

each one does its work:

V8 does a lot while your program runs: it parses, interprets bytecode
with Ignition, and compiles hot code<Cite id="v8-ignition" />. A Rust
program did all its compiling before it started.

<Callout kind="definition">
**Rust** is a compiled systems language. Its compiler, `rustc`, checks
types and memory-safety rules for the whole program, then produces
native machine code. The running program has no garbage collector and no
JIT: memory is freed at points the compiler works out in advance.
</Callout>

The costs are real, and you should hear them now. The compiler rejects
programs that TypeScript would happily run, and at first it will feel
like arguing with it. You wait for a full compile before every run. And
some designs
that are trivial with a GC, such as many objects all pointing at each
other, take more thought.

## Hello, Rust

Here is a complete Rust program:

```rust
fn main() {
    println!("Hello, Drip!");
}
```

`fn main()` is where every Rust program starts. There is no top-level
code as in a JavaScript file. `println!` plays the part of
`console.log`. The `!` marks it as a **macro**: code that writes code at
compile time. Forget the `!` and the compiler tells you so. This is the
real output of rustc 1.97:

```
error[E0423]: expected function, found
  macro `println`
 --> e1.rs:2:5
  |
2 |     println("Hello, Drip!");
  |     ^^^^^^^ not a function
  |
help: use `!` to invoke the macro
```

Rust's error messages are long and specific. Read them to the end: the `help:`
line often holds the fix. Inside the string, `{}` marks a gap that
`println!` fills with the next argument. Try it:

## cargo: Rust's npm

You can compile one file with `rustc main.rs`. Nobody does, past day
one. Real projects use **cargo**, which plays the parts of `npm`, `tsc`
and your test runner at once<Cite id="klabnik2026" />.

```
$ cargo new hello
$ cd hello
$ cargo run
   Compiling hello v0.1.0
    Finished `dev` profile
     Running `target/debug/hello`
Hello, world!
```

(Output from cargo 1.97, trimmed.) `cargo new` made two files:

```
hello/
├── Cargo.toml
└── src/
    └── main.rs
```

`Cargo.toml` is the `package.json`: a name, a version, an edition, and
a `[dependencies]` list. Packages come from crates.io, as npm packages
come from the npm registry.

```toml
[package]
name = "hello"
version = "0.1.0"
edition = "2024"

[dependencies]
```

The **edition** picks a version of the language's rules. New cargo
projects get 2024. This book's runnable examples use 2021, and nothing
in the next chapters differs between the two.

The everyday commands:

- `cargo check` type-checks without making a binary. It's the fast one,
  like `tsc --noEmit`.
- `cargo build` compiles to `target/debug/hello`. `cargo run` builds,
  then runs.
- `cargo build --release` turns on the optimizer and writes to
  `target/release/`. Debug builds are for working, release builds for
  measuring: drip-rs's numbers above are release numbers.

<Callout kind="definition">
**cargo** is Rust's build tool and package manager. A **crate** is the
unit `rustc` compiles in one go. A **binary crate** has a `main` and
becomes a program. A **library crate** has no `main`; other crates use
it. A **package** (one `Cargo.toml`) holds one or more crates.
</Callout>

drip-rs is a nice example. Its `Cargo.toml` declares a library crate,
`drip`, holding the scanner, compiler, VM and collector, and a binary
crate, `drip-rs`, a short `main` that reads a file and calls the
library.

<Callout kind="engine" label="Under the hood">
Viscosity rearranged arrays of objects into typed-array columns because
JavaScript hides layout. In Rust, a `Vec` of structs and a struct of
`Vec`s are both ordinary code you write, with no object headers in the
way. Chapter 317 builds the struct of arrays by hand. Part XIII then
rebuilds Viscosity itself in Rust: still a compiler for JavaScript, but
one whose own IR lives in memory it lays out on purpose.

## What you learned

- **Rust** compiles to machine code ahead of time, with no garbage
  collector and no JIT. The compiler checks memory safety before the
  program runs. The price is a stricter compiler and slower builds.
- In this book's run, the Rust port of the Drip VM was several times
  faster than the TypeScript VM. One run, one port, one machine.
- `fn main()` is the entry point. `println!` is a **macro**.
- **cargo** creates, checks, builds, runs and tests projects. `--release`
  turns on optimization.
- A **crate** is one compilation unit: a binary (with `main`) or a
  library.

Next, variables: Rust's `let` is TypeScript's `const`, and `number`
splits into a dozen types.
