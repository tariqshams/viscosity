## Lost in the middle of a statement

"Syntax errors and recovery" set the goals: report every real mistake
in one run, and none of the echoes. Here is the situation the parser
is in when it meets a mistake:

```text
let x = 1
x = 2;
print x;
```

It wanted a `;` after the `1` and found `x`. It has no idea what the
writer meant: a forgotten `;`, a stray `x`, or something else. If it
went on from the `x` as if nothing had happened, every token after it
would be read in the wrong frame of mind, and each one could produce a
fresh, made-up complaint. Drip's answer has two parts, both small: stay
quiet until the statement is over, then skip ahead to a place where it
is sure where it is. Together they are called panic mode.

<Analogy title="a pianist who loses their place">
A pianist who loses their place in a piece does not keep playing wrong
notes and hope; they skip to the start of the next bar, where they know
exactly where they are, and carry on from there.
<span slot="breaks">The audience hears the gap; nobody hears what a
parser skips, which is the danger: a second mistake inside the skipped
part goes unreported until the next run.</span>
</Analogy>

<Analogy title="a hiker who has lost the path">
A hiker who has wandered off the path does not try to guess a way
through the trees; they head for the next trail marker, where the map
makes sense again, and follow the path from there.
<span slot="breaks">A hiker can walk back to look again; a parser only
moves forward, and the tokens it passes on the way to the marker are
never checked.</span>
</Analogy>

## Part one: keep quiet

Every error goes through one function, `errorAt`, and it starts by
checking a flag:

```ts
function errorAt(token, message) {
  if (panicMode) return; // an echo
  panicMode = true;
  reporter.error(token.line, message);
}
```

The first error in a statement finds `panicMode` false, so it sets the
flag and reports. Any further error before the statement ends finds the
flag already set and returns without a word, because it is probably an
echo. That one `if` is the line I deleted in "Syntax errors and
recovery" to show what Drip would say without it: three messages for
`print (1 + ;` instead of one.

The flag is cleared by `declaration()`, the function that parses one
statement, when the statement is done:

```ts
function declaration(): Stmt {
  let s: Stmt;
  if (match('let')) s = letDeclaration();
  // … class, fn
  else s = statement();
  if (panicMode) synchronize();
  return s;
}
```

Nothing is thrown, so a failed `consume` reports and carries on,
building a statement that will never run, and `declaration` finishes
normally. Then, if anything went wrong, it calls `synchronize()`.

## Part two: skip to a safe point

`synchronize` clears the flag and throws tokens away until a new
statement probably starts:

```ts
function synchronize() {
  panicMode = false;
  let depth = 0;
  while (current.type !== 'eof') {
    if (depth === 0) {
      if (previous.type === ';') return;
      if (STATEMENT_STARTS.has(
          current.type)) return;
      if (current.type === '}' &&
          blockDepth > 0) return;
    }
    if (current.type === '{') depth++;
    else if (current.type === '}' &&
             depth > 0) depth--;
    advance();
  }
}
```

Each turn of the loop checks for a safe place, and if there is none,
`advance()` throws one token away. The three safe places: just after a
`;` (a statement has just ended); just before a keyword that begins a
statement (`STATEMENT_STARTS` is the set `class`, `fn`, `let`, `for`,
`if`, `while`, `print`, `return`, `break` and `continue`); and at a `}`
that closes the block the parser is in (`blockDepth` counts how many
blocks it is inside; the `}` itself is left for the block to take). The
`depth` counter handles braces opened *while skipping*: inside them,
nothing counts as safe, so a `{ … }` is skipped whole. The loop also
stops at the end of the file, because there is nothing left to skip.

<Callout kind="definition">
**Panic mode** is error recovery by skipping. On an error the parser
reports it, keeps quiet about any more errors in the same statement,
and then discards tokens until it reaches a **synchronisation point**
(a token after which the grammar is likely to make sense again), where
it resumes normal parsing.
</Callout>

<Formal title="Drip’s synchronisation points">

```text
stop before tₖ  ⇔  depth = 0 and
     ( tₖ₋₁ = ';'
     ∨ tₖ ∈ STARTS
     ∨ (tₖ = '}' ∧ inside a block) )
   or tₖ = eof
```

<span slot="read">Synchronize stops just before token t k when no
brace opened during the skip is still open, and either the token before
it is a semicolon, or t k is one of the statement keywords, or t k is a
closing brace and the parser is inside a block; it also stops at the
end of the file. The wedge-shaped symbol means or, and the upside-down
one means and.</span>
</Formal>

## What panic mode gives up

Skipping has a price, and it is visible in the step-through: `x = 2;`
was thrown away without being checked. Here is the same thing inside a
loop:

```text
while n > 0 {
  print n
  n -= 1;
}
# line 2: expected ';' after the
#   value, found 'n'
```

The `n` after the missing `;` is not a statement keyword, so it, the
`-=`, the `1` and the `;` are all skipped; a mistake in `n -= 1;` would
wait for the next run. Panic mode accepts that, because a missed error
costs one more run, while a made-up one costs confusion.

A missing `{` is handled the other way round. If a body's `{` is not
there, the parser reports it and parses no body at all, because what
follows is more likely the next statement than a body:

```text
let x = 2;
if x > 1 print x;
# line 2: expected '{' after the
#   condition, found 'print'
if x > 1 { print x; }  # 2
```

The `print` is then a safe point, so `print x;` is checked as a
statement of its own; the working version has the braces Drip always
needs.

Some errors cost almost nothing. For `a + b = 3;` the parser reads
`a + b`, takes the `=`, and reports `cannot assign to this expression`,
which sets the flag too. The statement then wants its `;` and finds the
`3` (that complaint is dropped as an echo), and `synchronize()` skips
only the `3` and the `;`, the rest of the same statement. The next
statement is checked as usual:

```text
a + b = 3;
print a +;
# line 1: cannot assign to this
#   expression
# line 2: expected an expression,
#   found ';'
```

## What you learned

- In **panic mode**, the parser reports the first error of a statement
  and drops the rest, which are probably echoes.
- Then `synchronize()` skips tokens to a **synchronisation point**:
  just after a `;`, before a statement keyword, or at the `}` closing
  the block, with any braces opened on the way skipped whole.
- The price is that skipped tokens are never checked; some errors,
  like `cannot assign to this expression`, skip only the end of their
  own statement.
- A missing `{` means no body is parsed, so what follows is checked as
  ordinary statements.
