## One argument short

The last chapter ended with a call expression that evaluates its callee
and its arguments and then runs the function. Here is a call that hands
it too little:

```
fn area(w, h) {
  print w * h;
}
area(3);
```

`area` was written to receive two values and `area(3)` gives it one.
Something has to happen at that call, and a language can choose: it can
fill the gap with some "nothing" value and carry on (JavaScript's
choice), or it can stop and say so (Drip's). This chapter is about that
choice, and then about the few functions, like `len` and `clock`, that
a Drip program needs but cannot write.

## Arity: the right number of arguments

`area` has two parameters, so `area(3)` leaves `h` with nothing to hold.
Drip does not guess what you meant; `callFunction` checks before
anything else:

```ts
if (args.length !== f.arity)
  throw new RuntimeError(at,
    `${f.label} takes ` +
    plural(f.arity, 'argument') +
    ` but got ${args.length}`);
```

`f.arity` is the number of parameters in the declaration, `f.label` is
the function's name with brackets (`area()`), or `anonymous fn` for one
without a name, and `plural` writes `1 argument` or `2 arguments`, so
`area(3)` stops with `area() takes 2 arguments but got 1`. The check
comes before the new environment is made, so a call with the wrong
count never runs a single line of the body.

<Analogy title="a recipe that wants two eggs">
A careful cook reading "beat two eggs" who finds only one in the box
stops before cracking anything, rather than making half an omelette and
hoping; the shopping is checked against the recipe first.
<span slot="breaks">A cook could improvise with one egg; Drip never
improvises, and it counts only how many arguments there are, not
whether they are the right kind (a string where a number belongs is
found later, when the body tries to use it).</span>
</Analogy>

<Analogy extra title="a table for two">
A restaurant booking "for two" sets two places; turn up as a group of
three and the waiter stops you at the door rather than seating you and
hoping a chair appears, and turn up alone and you are asked whether the
second guest is coming.
<span slot="breaks">A restaurant can squeeze in an extra chair or clear
a place; Drip has no such give, and a call with the wrong count is
stopped every time, with nothing run at all.</span>
</Analogy>

<Callout kind="definition">
A function's **arity** is the number of arguments it takes; for a Drip
function it is the number of parameters in its declaration, and each
native function has a fixed arity of its own. Drip checks arity on
every call, before the body runs, and a mismatch is a runtime error:
`area() takes 2 arguments but got 1`.
</Callout>

<Formal title="When a call may run">

```text
f = fn (p₁, …, pₙ) { body }
f(a₁, …, aₘ) runs body  ⟺  m = n
then  pᵢ ↦ value of aᵢ, for 1 ≤ i ≤ n
```

<span slot="read">If f is a function with n parameters, the call of f
with m arguments runs its body exactly when m equals n (the symbol ⟺
reads "exactly when"). If it does, each parameter number i is given the
value of argument number i, for every i from 1 to n.</span>
</Formal>

<Examples of="arity">

```
fn ping() { print "ok"; }
ping();   # ok: arity 0, got 0
```

```
fn area(w, h) { print w * h; }
area(3, 4); # 12
area(3);
# runtime error: area() takes
#   2 arguments but got 1
#   at line 3 in script
```

```
let sq = fn (x) { print x * x; };
sq(2, 3);
# runtime error: anonymous fn
#   takes 1 argument but got 2
#   at line 2 in script
```

</Examples>

The first shows that zero is an arity like any other: no parameters and
no arguments, so the call runs. The second puts the call that works
next to the classic slip, a forgotten argument: the error names the
function and both counts, and its `at line 3` points at the call that
forgot, which is where you would want to look (the chapter *Borrowing
the host's call stack* explains those `at` lines). The third is an anonymous function given
too many: it has no name, so the message calls it `anonymous fn`, and
`1 argument` is singular.

JavaScript is far more relaxed. A function does report how many
parameters it declares, as `f.length`<Cite id="mdn-function-length" />,
but a call never checks it: a missing argument leaves its parameter
`undefined`, and extra ones are kept aside where most code never looks
at them<Cite id="mdn-functions" />. Drip chooses to fail loudly, which
turns a forgotten argument into an error at the call that forgot it,
rather than an `undefined` that misbehaves somewhere far away.

## Native functions: help from the host

Some things cannot be written in Drip at all. Drip has no way to read
the time (no expression or statement asks the outside world anything),
and a list's length is not something a Drip program can work out by
itself. So the interpreter defines a few functions in TypeScript and
puts them in the globals before your program starts:

```ts
const native = (name, arity, fn) =>
  this.globals.define(name,
    new NativeFunction(name, arity, fn));
native('clock', 0, () =>
  (performance.now() - this.start) / 1000);
native('len', 1, ([x], at) => {
  if (x instanceof DripList)
    return x.items.length;
  if (typeof x === 'string')
    return [...x].length;
  throw new RuntimeError(at,
    `len() needs a list or a string, ` +
    `not ${describe(x)}`);
});
```

`native` is a small helper: it makes a `NativeFunction` holding a name,
an arity and a TypeScript function, and defines it as a global. `clock`
takes no arguments and returns the seconds since the program started,
using JavaScript's `performance.now()`, a fine-grained timer that counts
milliseconds<Cite id="mdn-performance-now" /> (hence the division by
1000). `len` takes one: for a list it returns how many items it holds,
for a string how many characters (`[...x]` counts whole Unicode
characters), and for anything else it throws a runtime error in Drip's
own words. `push`,
`pop` and `str` are built the same way. When the call expression meets a
`NativeFunction`, it checks the arity exactly as it does for a Drip
function (`len(1, 2)` is `len() takes 1 argument but got 2`) and then
runs `callee.fn(args, e.paren)`.

Guests who cannot leave the hotel can still get theatre tickets: they

</Analogy>

<Callout kind="definition">
A **native function** is a callable written in the host language (here
TypeScript) rather than in the language being run. Natives are how a
language reaches anything outside itself, such as the clock, files or
the screen, and how it offers operations that would be slow or
impossible to write in the language itself. Drip has five: `clock`,
`len`, `push`, `pop` and `str`; `print len;` shows `native fn len`.
</Callout>

<Examples of="native-function">

```
print len([4, 8, 15]); # 3
print len("drip");     # 4
```

```
let xs = [];
push(xs, "a");
push(xs, "b");
print pop(xs);  # b
print xs;       # ["a"]
print len(7);
# runtime error: len() needs a
#   list or a string, not a number
#   at line 6 in script
```

<Run id="timing" />

</Examples>

The first asks `len` about a list of three numbers and a string of four
characters. The second grows a list with `push`, takes the last item
back off with `pop` (which returns it, so `print` shows `b`), prints
what is left, and then hands `len` a number, which the TypeScript code
rejects with a message written in Drip's terms. The runnable one times a
loop with `clock`: it reads the clock, does some work, and prints the
difference (your number will vary from run to run, which the
benchmarking chapters had a lot to say about).

## What you learned

- A function's **arity** is how many arguments it takes. Drip checks it
  before every call and stops with `area() takes 2 arguments but got 1`
  (or `anonymous fn takes ...`); nothing in the body runs.
- JavaScript never checks: a missing argument is `undefined` and an
  extra one is ignored.
- A **native function** is written in the host language. Drip has five,
  `clock`, `len`, `push`, `pop` and `str`, defined as globals before the
  program starts.
- Calling a native checks its arity and runs its TypeScript code
  directly, with no Drip environment; its errors are written in Drip's
  words.
