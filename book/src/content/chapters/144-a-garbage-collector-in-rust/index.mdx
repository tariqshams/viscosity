## Who decides to collect?

The TypeScript heap of *Reclaiming memory: mark and sweep* collects from
inside `allocate`: it finds the roots through `heap.vm`, the compiler's
functions, and an `extraRoots` stack that protects a half-built value.
drip-rs cannot do that, because the heap is a field of the VM and
cannot borrow the VM back. So whoever allocates decides, from `vm.rs`
(rewrapped):

```rust
fn alloc<T: HeapObject>(
    &mut self, object: T) -> Gc<T> {
    self.collect_if_needed();
    self.heap.alloc(object)
}
```

`Heap::alloc` itself never collects. `collect_if_needed` asks
`self.heap.should_collect()`, true once the bytes allocated pass
`next_gc` (or always, in stress mode), and then builds the VM's roots
and calls `heap.collect`. The price is one rule, in the comment on
`Vm::alloc`: anything the new object refers to must already be
reachable from a root, the argument *Call frames and upvalues in Rust*
made for closures.

## Roots are trait objects

Anything that can report the handles it holds implements one trait, from
`gc.rs`, and the collector takes its roots as a slice of trait
objects<Cite id="rust-reference-trait-object" />:

```rust
pub trait Trace {
    fn trace(&self, marks: &mut Marks);
}

pub fn collect(&mut self,
               roots: &[&dyn Trace])
```

There are impls for `Gc<T>`, `StrRef`, `Value`, `Table`, `Option<T>`,
`[T]` and `Vec<T>`, so `self.stack.trace(marks)` marks a whole stack.
`dyn` is needed because one call mixes types: the VM passes a `VmRoots`
of borrowed fields (the stack, the frames, the globals, the open
upvalues); the compiler passes `&[self.roots, &self.functions]`, adding
its half-built functions (*A Pratt compiler in Rust*); and
`--disassemble`, with no VM at all, passes `&()`.

## Mark bits outside the objects

TypeScript objects have an `isMarked` field. Put a mark bit in each
object of a Rust arena, and marking what an object refers to fails
(rustc 1.97, on a toy, trimmed):

```text
error[E0502]: cannot borrow `*self` as
  mutable because it is also borrowed
  as immutable
for &r in &self.nodes[i].refs {
    self.mark(r); // sets a bit
```

Tracing reads objects; marking writes bits; with both in one struct,
the two borrows overlap. So drip-rs keeps the bits in a separate
`Marks` value, one `Vec<bool>` per arena plus the grey stack, and lifts
it out of the heap while it works. From `Heap::collect` (comments
trimmed):

```rust
let mut marks =
    std::mem::take(&mut self.marks);
marks.reset(self);
for root in roots {                  // 1.
    root.trace(&mut marks);
}
while let Some(object) = marks.gray.pop() {
    self.blacken(object, &mut marks); // 2.
}
self.interned.retain_keys(           // 3.
    |s| marks.strings[s.handle.index()]);
self.sweep(&marks);                  // 4.
self.marks = marks;
```

`mem::take` swaps an empty `Marks` in and hands back the real
one<Cite id="rust-std-mem-take" />, so `blacken(&self, object, &mut marks)`
borrows the heap shared and the bitmap mutably: two separate values.
`reset` clears every bit vector, so sweep never has to unmark survivors
(the TypeScript sweep does). Step 3 is the weak string table: entries
for unmarked strings are dropped before the strings are freed. The grey
stack holds a `Gray` enum, one variant per kind of object that can
refer to others; strings and natives go black at once.

<Callout kind="definition">
drip-rs's **arena GC** is mark and sweep over one arena per object type.
Marking fills a bitmap kept outside the objects (a `Vec<bool>` per
arena, cleared at the start of every collection), starting from roots
passed in as `&dyn Trace`. Sweeping visits every slot, frees each live
one whose bit is false, and pushes its index on that arena's **free
list**, which `Arena::insert` pops before growing the arena.
</Callout>

<Formal title="What survives a collection">

```text
R₀ = roots
Rₖ₊₁ = Rₖ ∪ { p | o ∈ Rₖ, o → p }
live = R, the first Rₖ with Rₖ₊₁ = Rₖ
freed = slots − live
```

<span slot="read">Start with the set of objects the roots name. Each
round, add every object that something already in the set refers to.
When a round adds nothing, the set is everything reachable, and that is
what survives; every other live slot is freed. The grey stack is the
round still to be done: the objects added but not yet looked inside.</span>
</Formal>

## Sweep, free lists and stress

Sweep runs over all nine arenas, freeing with `Arena::remove(i, reuse)`:
the slot is `take`n, so it becomes `None` and the object is dropped
(with its `Box<str>`, tables or `Vec`s), and if `reuse` is true the index
goes on the arena's free list. Pacing is the TypeScript VM's: `next_gc`
becomes twice what survived, but at least 1 MiB.

A missing root is the classic collector bug, and it hides: it bites only
if a collection runs at exactly the wrong moment. **Stress mode** makes
every moment that moment: `should_collect()` is always true, and
`reuse` is false, so a stale handle finds `None` and panics with "use
after free" instead of quietly reading whatever object moved in.
`tests/stress_gc.rs` runs 165 corpus programs from ten folders this way.

<Examples of="arena-gc">

```rust
// from the unit test in gc.rs
let class = heap.alloc(ObjClass {
    name: kept, methods: Table::new() });
heap.collect(&[&class]); // freed == 1
```

```text
test closures/assign_after_capture.drip
  ... FAILED
panicked at src/object.rs:143:5:
use after free: an object of type
ObjUpvalue was collected while still
in use
```

</Examples>

The first is the smallest collection: two interned strings, `"kept"`
and `"lost"`, and a class named `"kept"` as the only root. The class is
marked, blackening it marks its name, and `"lost"`, which nothing
reaches, is the one object freed. The second is a real bug, planted on
purpose: I deleted one line from a scratch copy of drip-rs,
`self.open_upvalues.trace(marks);` in `VmRoots`. The normal corpus suite
still passed, 334 of 334; the stress suite failed 25 of its 165
programs. The new upvalue was reachable only from the unrooted open
list, so the closure's own allocation freed it, and the next
`close_upvalues` panicked on the stale handle.

## What you learned

- The **arena GC** is handed its roots as `&dyn Trace`; allocation never
  collects by itself.
- Mark bits live in a bitmap taken out with `mem::take`; sweep frees
  onto per-arena free lists.
- Stress mode collects before every allocation and never reuses a slot,
  so a missing root panics.
