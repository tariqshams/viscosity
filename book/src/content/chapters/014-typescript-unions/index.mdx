## This or that

Some values honestly come in more than one kind. An id might be a number
(`42`) or a string (`'ada'`). Labelling it `number` would be a lie, and
so would `string`. TypeScript lets you say “either”:

```ts
function show(id: number | string) {
  return id.toUpperCase();
  // error: Property 'toUpperCase' does not
  // exist on type 'string | number'.
}
```

The checker is right to complain. If `id` is `42`, there is no
`toUpperCase` to call, and the program would crash.

<Callout kind="intuition">
A union is a parcel labelled “a book **or** a mug”. You can do things
that work on both (carry it, weigh it), but before you *read* it, you have
to open it and look. Opening the parcel is an `if`.
</Callout>

<Callout kind="definition">
A **union type** `A | B` labels a value that may be an `A` or a `B`.
Until you check which, the checker only allows operations that are safe
for every member of the union<Cite id="ts-everyday-types" />.
</Callout>

## Following the if

You already know the runtime check: `typeof`. Watch what the checker does
with it:

<NarrowSteps client:visible />

```ts
function show(id: number | string) {
  if (typeof id === 'string') {
    return id.toUpperCase(); // id: string
  }
  return id.toFixed(2);      // id: number
}
```

(`toFixed(2)` turns a number into text with two decimal places.) Inside
the `if`, only strings get through, so the checker treats `id` as a
`string` there. After the `if` returns, only numbers are left.

<Callout kind="definition">
**Narrowing** is the checker working out a more exact type from a check
in your code, like `typeof id === 'string'`. It follows every `if`,
`else` and `return`, so in each region of code it knows which members of
the union can still be there<Cite id="ts-narrowing" />. The check itself
is ordinary JavaScript that really runs. The narrowing is erased.
</Callout>

## Tagged variants

`typeof` can tell a number from a string, but not a circle from a
rectangle: both are just `'object'`. So we put a tag on every object.

<Callout kind="intuition">
Think of envelopes with a word stamped on the outside: “bill”, “letter”,
“postcard”. Read the stamp, and you know exactly what’s inside before you
open it.
</Callout>

```ts
type Shape =
  | { kind: 'circle'; r: number }
  | { kind: 'rect'; w: number; h: number };

function area(s: Shape): number {
  if (s.kind === 'circle') {
    return Math.PI * s.r * s.r;
  }
  return s.w * s.h;
}
```

`type Shape = ...` gives a name to a type, like `interface` does, but it
can name a union too. In `kind: 'circle'`, the type is the exact string
`'circle'` and nothing else. So checking `s.kind` tells the checker which
variant `s` is: inside the `if`, `s.r` is allowed; after it, `s.w` is.

<Callout kind="definition">
A **discriminated union** is a union of object types that all share one
property, the tag (here `kind`), with a different exact value in each.
Checking the tag narrows the whole object to one variant<Cite id="ts-narrowing" />.
</Callout>

## The shape of every syntax tree

Here’s why this chapter matters so much for the rest of the book. A
program’s code, once a parser has read it, is a **tree**, and each node in
the tree is one of a fixed set of kinds. That is exactly a discriminated
union:

```ts
type Expr =
  | { kind: 'num'; value: number }
  | { kind: 'add'; left: Expr; right: Expr }
  | { kind: 'mul'; left: Expr; right: Expr }
```

<Figure takeaway="A syntax tree is a discriminated union, nested." caption="(1 + 2) * 4 as Expr objects. Each node’s kind says which variant it is; add and mul nodes hold two smaller Expr nodes, so the type refers to itself.">
  <ExprTree />
</Figure>

Real JavaScript tools do exactly this. In ESTree, the tree format many
JavaScript tools share, every node has a string `type` field that says
which kind of node it is<Cite id="estree" />. You’ll walk a tree like this
recursively in this chapter’s exercise, and that walk is your first
interpreter.

## Proving every case is handled

Suppose you add a third shape, `{ kind: 'tri'; b: number; h: number }`,
and forget to update `area`. You want the checker to notice. Here is the
standard trick:

```ts
function unreachable(x: never): never {
  throw new Error('unhandled case');
}

function area(s: Shape): number {
  if (s.kind === 'circle') {
    return Math.PI * s.r * s.r;
  }
  if (s.kind === 'rect') {
    return s.w * s.h;
  }
  return unreachable(s);
}
// error: Argument of type '{ kind: "tri";
// b: number; h: number; }' is not
// assignable to parameter of type 'never'.
```

`never` is the type with *no* values at all. When every kind has been
handled, narrowing leaves nothing for `s` to be by the last line, so `s`
is `never` and the call is fine. Forget `'tri'`, and `s` could still be a
triangle there, so the checker points straight at the gap.

<Callout kind="definition">
**Exhaustiveness checking** makes the checker prove every member of a
union is handled: after all the checks, the leftover type must be
`never`<Cite id="ts-narrowing" />. Keep the `throw` inside `unreachable`
anyway. Types are erased, so if bad data ever does arrive, you get a clear
error instead of a wrong answer.
</Callout>

## Types with blanks: generics

What is the type of a function that returns the first item of any list?
`first(xs: number[]): number` works only for numbers. Writing the same
function again for strings would be silly.

<Callout kind="intuition">
A generic is a label with a blank in it: “a box of ____”. Each time you
use it, the blank is filled in: a box of numbers, a box of strings. The
blank is written `T`.
</Callout>

```ts
function first<T>(xs: T[]): T | undefined {
  return xs[0];
}

const a = first([1, 2]);
// a: number | undefined
const b = first(['x']);
// b: string | undefined
```

`<T>` declares the blank. The checker fills it in from each call, so `a`
is labelled a number (or `undefined`, for an empty list) and `b` a
string. You’ve already met one generic: `Array<number>` is another way to
write `number[]`.

<Callout kind="definition">
A **generic** is a function or type with a **type parameter**, like `T`,
that is filled in each time it is used. `Array<T>` is a generic type, and
`first<T>` is a generic function<Cite id="ts-generics" />.
</Callout>

## What you learned

- A **union type** `A | B` holds either. Until you check, only things safe
  for both are allowed.
- **Narrowing**: the checker follows your `typeof` and `kind` checks, and
  your returns, to know the exact type in each region of code.
- A **discriminated union** tags each variant with a `kind`. It is the
  shape of every syntax tree and instruction in this book.
- **Exhaustiveness**: end with `unreachable(x: never)`, and the checker
  proves every case is handled. Keep the runtime `throw` too.
- A **generic** like `first<T>` has a type parameter that each use fills
  in.
