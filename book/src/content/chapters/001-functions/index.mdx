## Same work, written twice

Say you are working out the areas of a few rectangles, and you write
this:

```js
console.log(3 * 4); // 12
console.log(5 * 2); // 10
console.log(7 * 6); // 42
```

Each line multiplies a width by a height and prints it; it works, however
the *idea* ("width times height") is written out three times, glued to
different numbers, and if the idea changed (say every rectangle needed a
border first) you would fix it in every place. We want to write the idea
down **once**, give it a name, and use the name whenever we need it.

<Analogy title="a recipe card">
You write the steps for pancakes on a card once, title it "pancakes" and
put it on the shelf; writing the card cooks nothing. Later, whenever you
want pancakes, you take the card down and follow it, as many times as you
like. Writing the card is **defining** a function; following it is
**calling** it.
<span slot="breaks">A cook reads a recipe loosely, tastes and adjusts; the
computer follows the steps exactly as written, every time, with no
judgement of its own.</span>
</Analogy>

<Analogy title="a contact saved in your phone">
Saving "Mum" with her number in your contacts does not ring anyone; it
only means that from now on you can reach her by name. Tapping the name
is what places the call.
<span slot="breaks">A phone call can go unanswered or reach the wrong
person; a function call always runs exactly the steps you wrote, and it
always finishes before your next line runs.</span>
</Analogy>

## Defining and calling

Here is the picture to keep in your head: a function is a small machine,
where you drop a value in at the top, the machine does its work, and a
value comes out at the bottom.

<Figure takeaway="A function turns an input into an output." caption="The value you pass in (3) lands in the name n. The body does the work, and the value after return (6) comes out.">
  <FunctionMachine />
</Figure>

In JavaScript that machine is written like this:

```js
function double(n) {
  return n * 2;
}

console.log(double(3)); // 6
```

Line 1 says "here is a **function** called `double`; it will be handed
one value, which it will call `n`", and the curly brace opens its
**body**, the steps it runs. Line 2 is the only step: work out `n * 2`
and send the answer back (more on `return` below); line 3 closes the
body. Those three lines **define** the function and compute nothing. The
last line **calls** it: `double(3)` runs the body with `n` set to `3`,
the call produces `6`, and `console.log` prints it.

<Callout kind="definition">
A **function** is a named block of code that runs only when it is called.
You **call** it by writing its name followed by parentheses, with the
values it needs inside them: `double(3)`. One definition can be called
any number of times<Cite id="mdn-functions" />.
</Callout>

<Examples of="function call">

```js
double(10); // 20
```

```js
double(2) + double(5); // 4 + 10, so 14
```

```js
function isDigit(c) {
  return c >= '0' && c <= '9';
}
isDigit('7'); // true
isDigit('x'); // false
```

</Examples>

The first is the smallest call there is: the name, the value in
parentheses, and the whole call produces `20`. The second shows a call
inside a bigger calculation: each call runs on its own and is replaced by
its answer, leaving `4 + 10`. The third is real: in Part III you will
write a *scanner* (the part of an interpreter that reads code one
character at a time), and it keeps asking "is this a digit?"; `isDigit`
checks that the character `c` is at least `'0'` and (`&&`) at most
`'9'` and sends back `true` or `false`.

A common slip is calling a name that was never defined, often a typo:

```js
function double(n) { return n * 2; }
doubel(3);
// ReferenceError: doubel is not defined
double(3); // 6
```

JavaScript finds no function called `doubel` and stops with that exact
message; spelled correctly, the call works.

## Parameters and arguments

`double` would be useless if it could only double `3`; the name `n` is a
blank that each call fills with a different value.

<Analogy title="a form with blanks">
A birthday card printed with "Happy birthday, ______!" has a blank with a
label under it ("name"). Each card you send gets a different name written
in: "Ada" on one, "Alan" on the next. The labelled blank is the
**parameter**; what you write in it is the **argument**.
<span slot="breaks">A paper card is used up once you write on it; a
function hands out a fresh, empty blank on every call, so writing "Ada" in
one call never leaves "Ada" behind for the next.</span>
</Analogy>

<Callout kind="definition">
A **parameter** is a name in a function's definition, inside the
parentheses, that stands for a value the function will be handed. An
**argument** is the actual value written in a call. When the function is
called, each parameter holds the argument in the same position: the
first argument goes to the first parameter, the second to the second.
</Callout>

To keep them apart: the **p**arameter is the **p**laceholder, written
once; the **a**rgument is the **a**ctual value, which can be different on
every call.

<Examples of="parameter argument">

```js
function area(w, h) { return w * h; }
area(3, 4); // w = 3, h = 4, so 12
```

```js
area(4, 3); // also 12
function minus(a, b) { return a - b; }
minus(10, 3); // 7
minus(3, 10); // -7
```

```js
function greet(name, hour) {
  if (hour < 12) return 'Morning, ' + name;
  return 'Hello, ' + name;
}
greet('Ada', 9); // 'Morning, Ada'
```

</Examples>

In the first, `area` has two parameters and the call has two arguments,
matched by position: `w` holds `3` and `h` holds `4`. The second shows
why position matters: swapping `area`'s arguments happens to give the
same answer, but `minus(10, 3)` is `7` while `minus(3, 10)` is `-7`. In
the third the arguments are a string and a number; `greet` uses the
number to choose a greeting (an `if` with a one-line body may leave out
the braces) and joins the name on with `+`.

<OtherLanguages>

```js
function area(w, h) {
  return w * h;
}
console.log(area(3, 4)); // 12
```

```python
def area(w, h):
    return w * h

print(area(3, 4))  # 12
```

```java
static int area(int w, int h) {
    return w * h;
}
// inside main:
System.out.println(area(3, 4)); // 12
```

```c
int area(int w, int h) {
    return w * h;
}
/* inside main: */
printf("%d\n", area(3, 4)); /* 12 */
```

</OtherLanguages>

The shape is the same in all four: a name, parameters in brackets, a
body and `return`. The real differences: Python uses `def` and marks the
body by indenting it; Java and C make you write the **type** of every
parameter and of the answer (`int` is a whole number) and check them
before the program runs, while JavaScript checks none (TypeScript, in
chapter 27, adds them back); and a Java function must live inside a
class, hence `static`.

## Getting a value back out: return

The keyword `return` does two jobs. It decides **what value comes out**:
the call is replaced by that value, as if you had typed it yourself, so
`double(3) + 1` is `7`. And it **stops the function** at once, skipping
any lines after it. Step through a call being replaced by its value:

<ReplaceSteps client:visible />

<Analogy title="a vending machine">
You put in coins (the arguments), press the button (the call), and the
machine drops a can into the tray (the return value); once the can drops,
that purchase is over, and the machine does nothing more for it, exactly
as `return` ends the call.
<span slot="breaks">A vending machine can run out of cans and keeps your
coins; a function can be called forever, and the value you pass in (a
number, at least) is still yours afterwards. Chapter 7 shows the twist
when you pass in a list or an object.</span>
</Analogy>

<Callout kind="definition">
A **return statement**, `return value;`, ends the current call and makes
it produce `value`. A function may have several; the first one that runs
is the one that counts.
</Callout>

<Examples of="return">

```js
function inc(n) { return n + 1; }
inc(inc(1)); // 3
```

```js
function sign(x) {
  if (x < 0) return 'negative';
  if (x === 0) return 'zero';
  return 'positive';
}
sign(-5); // 'negative'
```

```js
function lineCost(price, qty) {
  const total = price * qty;
  if (qty >= 10) return total * 0.9;
  return total;
}
lineCost(2, 10); // 18
```

</Examples>

In the first, the inner call runs first: `inc(1)` returns `2`, which
becomes the outer call's argument, so the answer is `3`. In the second
(where `===` asks "is equal to?"),
`sign(-5)` finds `x < 0` true and returns `'negative'`, and the function
stops, so the other two lines never run. The third is the kind of
function a shop's website has: line 2 keeps the total in a variable,
`total` (`const` makes a variable that is never given a new value; `let`
makes one that can be), line 3
returns early with ten per cent off (`total * 0.9`) for ten items or
more, and line 4 returns the plain total otherwise, so `lineCost(2, 10)`
is `20 * 0.9`, which is `18`.

<Formal title="A function in maths notation">

```text
double : number → number
double(n) = n × 2
double(3) = 3 × 2 = 6
```

<span slot="read">The first line says double takes a number and gives back
a number. The second says that for any n, double of n is n times two. The
third is a call: to work out double of 3, write 3 wherever n appears, and
the call is equal to the answer. (JavaScript functions can also print
things, which a maths function never does; chapter 27 writes the first
line as a TypeScript type.)</span>
</Formal>

Try it: change the numbers, or write a `triple` of your own.

## What you learned

- A **function** names a piece of work; **calling** it (`name(args)`)
  runs it.
- **Parameters** are the names in the definition; **arguments** are the
  values in a call, matched by position.
- `return` picks the value the call is replaced by, *and* stops it.
