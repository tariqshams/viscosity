## Remembering things about objects

You want to note which particles have already been hit. An object seems
like a good place to keep notes, with bracket access from chapter 3:

```js
const hit = {};
const a = { id: 1 };
const b = { id: 2 };

hit[a] = true;
console.log(hit[b]); // true ?!
```

`b` was never hit, yet the answer is `true`. A property name is always a
string, so JavaScript first turns `a` into a string, and every plain
object turns into the same string: `'[object Object]'`. So `hit[a]` and
`hit[b]` are the same property. The same thing happens with numbers:
`hit[1]` and `hit['1']` are one property too.

What you need is a lookup table whose keys can be *anything*, kept exactly
as they are.

<Callout kind="intuition">
A Map is a two-column table. On the left go the keys, on the right the
values. You find a row by its key, and the key can be any value at all: a
string, a number, even an object.
</Callout>

`Map` is a class, so you make one with `new` and use its methods:

```js
const ages = new Map();
ages.set('ada', 36);
ages.set('alan', 41);

console.log(ages.get('ada'));  // 36
console.log(ages.get('bob'));  // undefined
console.log(ages.has('alan')); // true
console.log(ages.size);        // 2
ages.delete('alan');
```

Object keys are compared by identity, exactly like `===` in chapter 4. So
the particle problem goes away:

```js
const hit = new Map();
hit.set(a, true);
console.log(hit.has(a));        // true
console.log(hit.has(b));        // false
console.log(hit.has({ id: 1 })); // false
```

The last line is a lookalike, a different object, so it isn't found.

<Callout kind="definition">
A **Map** holds key → value entries<Cite id="mdn-map" />. `set(k, v)` adds
an entry, or replaces the value if `k` is already there. `get(k)` returns
the value, or `undefined` if there is none. `has(k)` asks whether `k` is
there, `delete(k)` removes it, and `size` counts the entries. Keys can be
any value. They are compared like `===`, so objects match only themselves.
Each key appears at most once.
</Callout>

Here is the most common Map job of all, counting:

```js
const cs = ['red', 'blue', 'red'];
const counts = new Map();
for (let i = 0; i < cs.length; i++) {
  const c = cs[i];
  if (counts.has(c)) {
    counts.set(c, counts.get(c) + 1);
  } else {
    counts.set(c, 1);
  }
}
console.log(counts);
// Map(2) { 'red' => 2, 'blue' => 1 }
```

## for...of

Notice the counting loop only uses `i` to fetch `cs[i]`. When you don't
care about the index, there's a shorter loop.

<Callout kind="intuition">
A `for` loop with `i` says "for each slot number, look in that slot". A
`for...of` loop says "for each thing in here". You get the things
directly.
</Callout>

```js
for (const c of ['red', 'blue']) {
  console.log(c);
}

for (const entry of counts) {
  console.log(entry[0], entry[1]);
}
// red 2
// blue 1
```

Looping over a Map gives you each entry as a two-slot array:
`[key, value]`. Entries come out in the order their keys were first
added<Cite id="mdn-map" />. You'll often see this written
`for (const [k, v] of counts)`, a shorthand that unpacks the two slots into
the names `k` and `v`.

<Callout kind="definition">
**`for (const x of things)`** runs the body once for each value in
`things`, in order, with `x` holding that value<Cite id="mdn-for-of" />.
It works on arrays, strings, Maps and Sets. It doesn't work on plain
objects, and it doesn't give you the index: if you need `i`, use the
classic `for` loop.
</Callout>

## Set

Sometimes there's no value to store: you only want to know *whether*
something is in the collection. That's a Set.

```js
const tags = new Set();
tags.add('fast');
tags.add('red');
tags.add('fast'); // already there

console.log(tags.size);       // 2
console.log(tags.has('red')); // true

const ids = new Set([3, 1, 3, 3, 2]);
console.log(ids); // Set(3) { 3, 1, 2 }
```

<Callout kind="definition">
A **Set** is a collection of unique values<Cite id="mdn-set" />. `add(v)`
puts `v` in, and does nothing if it's already there. `has(v)` asks whether
it's there, `delete(v)` removes it, and `size` counts the values. It uses
the same idea of "the same value" as Map keys, and `new Set(array)` is the
quickest way to drop duplicates.
</Callout>

## How can a lookup be fast?

To find `'pink'` in an array of a million names, a loop checks name after
name, a million in the worst case. A Map gets there almost directly,
however many entries it holds. How?

<Callout kind="intuition">
Think of a post room with a wall of pigeonholes. Each letter's address
decides its pigeonhole. To find a letter, you don't read every letter in
the building: you work out which pigeonhole it belongs in, and look only
there.
</Callout>

<HashSteps client:visible />

<Callout kind="definition">
**Hashing**, the intuition: a *hash function* turns a key into a number,
and that number picks a bucket. Storing and finding a key both look only
inside its bucket. When keys spread evenly across enough buckets, each
bucket holds just a few entries, so a lookup stays quick however big the
table grows. A table organised like this is a **hash table**.
</Callout>

<Prompts ids={['hash-why-fast', 'hash-collision']} />

<Callout kind="engine" label="Under the hood">
The JavaScript standard doesn't say how `Map` and `Set` must be built. It
only requires that, on average, a lookup's cost grows more slowly than the
number of entries<Cite id="mdn-map" />. V8 builds `Map`, `Set`, `WeakMap`
and `WeakSet` on hash tables. For an object key, V8's hash code is simply a
random number, unrelated to what the object contains, so it can't be
recomputed and has to be stored with the object<Cite id="gunasekaran2018" />.
That fits Map's rule that objects are compared by identity, not contents.

You'll build a hash table from scratch in chapter 78, and your virtual
machine will keep its global variables in one. Engines use them for
ordinary objects too: V8 switches an object's property storage to a
dictionary, a hash table, once it holds a great many
properties<Cite id="gunasekaran2018" />, which you'll meet in chapter 90.
And compilers, Viscosity included, lean on lookup tables constantly: from
each name to its declaration, from each value to what is known about it.
</Callout>

## What you learned

- Object property names are always strings, so objects make poor lookup
  tables for non-string keys.
- A **Map** stores key → value entries, with keys of any type, compared
  like `===`. Use `set`, `get`, `has`, `delete` and `size`.
- A **Set** stores unique values. Use `add`, `has`, `delete` and `size`.
- **`for...of`** visits each value of an array, string, Map or Set, in
  order. Over a Map, each value is a `[key, value]` pair.
- **Hashing** turns a key into a bucket number, so a lookup checks one
  bucket instead of everything.
