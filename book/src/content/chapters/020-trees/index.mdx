## A box of boxes

Here is a folder on a computer, written as objects: a folder has a name
and an array of the things inside it, and some of those things are
folders too.

```js
const docs = {
  name: 'docs',
  children: [
    { name: 'a.txt', children: [] },
    { name: 'pics', children: [
      { name: 'cat.png', children: [] },
    ] },
  ],
};
```

`docs` holds two things: a file, `a.txt` (whose `children` array is
empty), and a folder, `pics`, which holds a file of its own. How many
items are there in total? One `for` loop can visit the children of
`docs`; reaching inside `pics` needs a loop inside that loop, and a
folder inside `pics` would need a third. You do not know how deep the
folders go until the program runs, and you cannot write "as many nested
loops as it takes". However, you can write a function that handles one
folder and calls itself for each folder inside it, which is exactly what
the last chapter's recursion is for.

<Analogy title="a family tree">
Draw one great-grandmother at the top, her children below her, their
children below them. Every person in the drawing is the top of a smaller
family tree of their own, and the people with no children are at the
bottom edge.
<span slot="breaks">Real families merge (everyone has two parents, and
cousins can marry); in a data tree, every node except the top one has
exactly one parent, so no two branches ever join up again.</span>
</Analogy>

<Analogy extra title="a book's table of contents">
A book has parts, a part has chapters, a chapter has sections, and a
section may have sub-sections; each heading is a smaller outline in its
own right, and the smallest headings contain only text.
<span slot="breaks">A table of contents is printed in one fixed order;
a program can visit a tree's nodes in whatever order it likes, such as
all the children before the parent, as the interpreter below does.</span>
</Analogy>

<Callout kind="definition">
A **tree** is data made of **nodes**, where each node can hold **child**
nodes, which are trees themselves (each child is a **subtree**). The node
at the top is the **root**; nodes with no children are **leaves**; every
node except the root has exactly one **parent**. A recursive function
walks a tree by handling one node and calling itself on each child, and
the leaves are its base case.
</Callout>

## Walking a tree

Counting every item is now three ideas: count this node, add the count
of each child (which is a whole tree, so `count` can do it), and hand
back the total.

```js
function count(node) {
  let total = 1; // this node
  for (const c of node.children) {
    total = total + count(c);
  }
  return total;
}

console.log(count(docs)); // 4
```

Line 2 counts the node itself. Lines 3 to 5 visit each child and add
whatever `count` says about it, which may mean many calls deeper. Line 6
hands back the total. There is no `if` anywhere, yet there is a base
case: a leaf has an empty `children` array, so its loop runs zero times
and it returns `1`. Step through it, watching the stack grow as deep as
the tree:

<CountSteps client:visible />

<Formal title="A tree, and its count, defined by recursion">

```text
Tree  ::= node(name, [Tree, …, Tree])
count(node(n, [t₁, …, tₖ]))
      = 1 + count(t₁) + … + count(tₖ)
```

<span slot="read">The first line reads: a Tree is a node holding a name
and a list of zero or more Trees (the symbol ::= reads "is made of"). The
second says: the count of a node with children t one to t k is one, for
the node itself, plus the count of each child. For a leaf, k is zero, so
its count is just 1: the definition of a tree and the function that walks
it have the same shape.</span>
</Formal>

Spot the difference: leave out the node itself, and nothing is ever
counted.

```js
let total = 0; // count(docs) is 0
let total = 1; // count(docs) is 4
```

With `0`, every leaf returns `0`, so every parent adds up zeros.

## Programs are trees

The expression `(2 + 3) * 4` is a multiplication whose left side is an
addition, which is a tree:

<Figure takeaway="Each node holds smaller trees." caption="(2 + 3) * 4 as a tree. The root is a mul node. Its left child is an add node, whose children are the leaves 2 and 3. Its right child is the leaf 4. The brackets have disappeared: the shape of the tree says what happens first.">
  <TreePicture />
</Figure>

```js
const tree = {
  kind: 'mul',
  left: {
    kind: 'add',
    left: { kind: 'num', value: 2 },
    right: { kind: 'num', value: 3 },
  },
  right: { kind: 'num', value: 4 },
};
```

Each node has a `kind`: a `'num'` node is a leaf holding a number, and an
`'add'` or `'mul'` node has a `left` and a `right` child, which can be any
kind of node. The brackets in `(2 + 3) * 4` are gone, because they are
not needed any more: the addition is *inside* the multiplication, so it
must be worked out first. A tree like this, built from a program's text,
is called a **syntax tree**, and in Part III your parser will build them.

<Examples of="tree">

```js
const seven = { kind: 'num', value: 7 };
// a tree with one node: root and leaf
```

<Run id="count-tree" />

```js
function show(t) {
  if (t.kind === 'num') return '' + t.value;
  const l = show(t.left);
  const r = show(t.right);
  if (t.kind === 'add') {
    return '(' + l + ' + ' + r + ')';
  }
  return '(' + l + ' * ' + r + ')';
}
show(tree); // '((2 + 3) * 4)'
```

</Examples>

The first is the smallest tree there is: one node, which is the root and
a leaf at once. The runnable one counts the folder tree; add a folder
inside `pics` and watch the count change, with no change to `count`.
The third turns a syntax tree back into text, and it is realistic (your
interpreter will have a printer like it, for debugging): a `num` leaf is
its number turned into a string (`'' + 7` is `'7'`); any other node shows
its left side, then its right side, and puts them back together with the
operator and a pair of brackets, so the output has brackets around every
operation, which shows exactly how the tree is grouped.

<OtherLanguages>

```js
const f = { name: 'a', children: [] };
const d = { name: 'docs',
            children: [f] };
```

```python
f = {'name': 'a', 'children': []}
d = {'name': 'docs', 'children': [f]}
```

```java
record Node(String name,
            List<Node> children) {}
var f = new Node("a", List.of());
var d = new Node("docs", List.of(f));
```

```c
struct Node {
    const char *name;
    struct Node **children;
    int n_children;
};
```

</OtherLanguages>

JavaScript and Python nest objects (or dictionaries) inside each other
freely, so a tree needs no declaration. Java wants a declared type first
(a `record` is a short way to write a class that only holds fields), and
its children are a typed `List`. C needs the most: a struct cannot hold
other structs of its own type directly, only point at them (that is what
the `*` marks, an idea Part II explains), and because C arrays do not know their own length (chapter 3),
the node must carry a separate count of its children.

</Callout>

## What you learned

- A **tree** is nodes holding child nodes, each of which is a smaller
  tree; the top is the **root**, the childless nodes are **leaves**.
- A recursive function walks a tree by handling one node and calling
  itself on each child; the leaves are the base case, often hidden in a
  loop that runs zero times.
- A program is a tree too: in `(2 + 3) * 4` the addition is a child of
  the multiplication, so the brackets are no longer needed.
