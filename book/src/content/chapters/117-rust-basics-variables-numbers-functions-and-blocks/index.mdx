## A counter that will not count

In TypeScript, `let x = 5; x = 6;` is fine. In Rust, rustc 1.97 refuses
with ``error[E0384]: cannot assign twice to immutable variable `x` ``,
and its `help:` line shows the fix, `let mut x = 5;` (rustc's messages
in this book are real, wrapped to fit your screen). This chapter is a
short tour of what looks like TypeScript but is not quite: variables,
numbers, functions and blocks.

<Analogy title="ink and pencil">
A plain `let` writes the value in ink: once it is on the page it stays.
`let mut` writes it in pencil, so you may rub it out and write a new one
as often as you like. Anyone reading the page can tell at a glance which
entries were written in pencil, and so which ones might have changed
since they last looked.
<span slot="breaks">Ink can still be scribbled over by a determined
hand; Rust's compiler refuses to build a program that writes to
a variable without `mut`, so there is no way round it.</span>
</Analogy>

## let, let mut and shadowing

The mapping is the wrong way round from what you might guess: Rust's
`let` is TypeScript's `const`, and TypeScript's `let` is `let mut`. Step
through it (locked boxes are plain `let`, open ones `let mut`):

<BindingSteps client:visible />

<Examples of="let-mut">

```rust
let total = 10;
let mut left = total;
left -= 3;
let xs = vec![1, 2];
// xs.push(3); // E0596: needs `let mut`
let x = "5";
let x = 5; // shadowing: a new x
```

</Examples>

`total` never changes; `left` goes down by 3, so it needs `mut`. Unlike
`const`, an immutable binding covers the whole value, so you cannot even
`push` onto `xs` (`vec!` makes a growable array, a `Vec`). The last two
lines are **shadowing**: a second `let` makes a new variable that hides
the old one until the end of its block, so it may have a new type, while
a `mut` variable keeps its type. (Rust's `const`, as in
`const MAX_SLOTS: usize = 256;`, is fixed before the program runs.)

<Callout kind="definition">
`let` binds a name to a value. Without `mut` the binding is
**immutable**: assigning to it, or changing the value through it, is a
compile error. `let mut` makes it **mutable**, always with a value of
the same type<Cite id="rust-book-variables" />. A second `let` with the
same name **shadows** the first: it is a new variable.
</Callout>

## One number becomes many

TypeScript has one `number`, a 64-bit float (V8's Smis are the engine's
choice, not yours). Rust makes you choose, and a value takes exactly the
room its type says:

<Figure takeaway="Rust's number types say how many bytes a value takes." caption="Sizes on a 64-bit machine, from std::mem::size_of with rustc 1.97. usize matches the machine's pointer width.">
  <TypeWidths />
</Figure>

`i8` to `i128` are signed and `u8` to `u128` unsigned (the number is
the width in bits); `usize`, as wide as an address, is for indexes and
lengths; `f64` is JavaScript's number; and `char` is one Unicode scalar
value in four bytes, written `'é'`. With nothing else to go on, a whole number is
an `i32` and a decimal an `f64`<Cite id="rust-book-data-types" />. Nothing
converts silently (an `i32` plus an `f64` is E0277, "cannot add `f64` to
`i32`"), so you convert with `as`, where a reader can see it:

<Run id="types" />

</Examples>

Run it. `a / 2` prints `3`: **dividing two integers gives an integer**,
cut toward zero (`-7 / 2` is `-3`). `as` can lose a great deal: `300` as
a `u8` keeps the low eight bits, 44, and `3.9 as i32` is
3<Cite id="rustref-operator-expr" />. The last surprise is overflow:

<OverflowSteps client:visible />

In a debug build (what `cargo run` and `cargo test` make), `255_u8 + 1`
stops the program with a **panic**, Rust's "stop now with a message":
`thread 'main' (23000) panicked at src/main.rs:3:5: attempt to add with
overflow` (the bracketed thread id changes from run to run). A release
build leaves the check out and wraps to 0<Cite id="cargo-profiles" />,
but the overflow is a bug either
way<Cite id="rustref-overflow-not-unsafe" />: ask for wrapping on
purpose with `wrapping_add`.

<Callout kind="definition">
The **scalar types** hold a single value: the integers `i8` to `i128`
and `u8` to `u128`, plus `isize` and `usize`; the floats `f32` and
`f64`; `bool`; and `char`, a four-byte Unicode scalar value. Integer
literals default to `i32` and decimals to `f64`.
</Callout>

## Functions: every signature complete

<Figure takeaway="Every parameter has a type, and the arrow says what comes back." caption="The parts of a Rust signature. The TypeScript signature says the same thing, but its types are optional and erased.">
  <SignatureParts />
</Figure>

A Rust function is a TypeScript one with `fn`, a snake_case name and
`-> T` for the return type; however, every parameter type is required,
and rustc checks every call against it before the program is built (one
argument short is E0061, a float for an `i32` is E0308). There are no
default parameters and no overloads<Cite id="rust-book-functions" />.

<Examples of="rust-functions">

```rust
fn is_digit(c: u8) -> bool {
    return c >= b'0' && c <= b'9';
}
fn report(n: i32) {
    println!("{n} found");
}
```

</Examples>

`is_digit` takes a byte (`b'0'` is a byte literal, the `u8` 48) and
returns a `bool`. `report` has no arrow, so it returns `()`, called
**unit**, which plays the part of `void`; forget the arrow on a function
that returns a number and rustc says "expected `()`, found `i32`".

<Callout kind="definition">
A **Rust function** is `fn name(param: Type, ...) -> Ret` followed by a
body in braces. Every parameter needs a type, and every call must pass
one argument of the right type per parameter, which rustc checks before
the program runs. A function with no `->` returns `()`, the **unit**
value<Cite id="rust-book-functions" />.
</Callout>

## Blocks and if have values

TypeScript needs a ternary because its `if` is a statement. In Rust a
block `{ ... }` is worth its last expression, written **without** a
semicolon<Cite id="rustref-block-expr" />, and an `if` is worth the value
of the branch that ran<Cite id="rustref-if-expr" />.

<Figure takeaway="The semicolon after the last line decides what a block is worth." caption="The same block twice. Without the semicolon, a + 1 is the block's value; with it, the block ends in a statement and is worth (), the unit value.">
  <SemicolonSwitch />
</Figure>

A function body is a block too, so its last expression is the return
value, and `return` is kept for leaving early. Step through `clamp`,
which is one `if` expression and nothing else:

<ExprSteps client:visible />

<Examples of="expression-oriented">

```rust
fn sign(n: i32) -> i32 {
    if n < 0 { -1 }
    else if n == 0 { 0 }
    else { 1 }
}
fn inc(x: i32) -> i32 {
    x + 1; // broken: the ; makes it ()
}
```

</Examples>

`sign` is one `if` expression whose branches are each worth an `i32`.
In exchange, every branch must have one type (`if b { 1 } else { "no" }`
is E0308, where TypeScript would infer `number | string`), an `if` used
for its value needs an `else` (E0317), and the condition must be a real
`bool`. `inc` is the famous mistake, and rustc points straight at it:

```text
error[E0308]: mismatched types
1 | fn inc(x: i32) -> i32 {
  |    ---            ^^^ expected `i32`,
  |    |                  found `()`
  |    implicitly returns `()` as its body
  |    has no tail or `return` expression
2 |     x + 1;
  |          - help: remove this semicolon
  |            to return this value
```

<Callout kind="definition">
Rust is **expression-oriented**. A block evaluates to its final
expression, or to `()` if it ends in a statement. `if` is an expression:
every branch must have the same type, and an `if` without `else` has
type `()`. A `;` after an expression turns it into a statement and
throws its value away<Cite id="rust-book-functions" />.
</Callout>

<Prompts ids={['ex-semicolon']} />

<More title="More: the four topics side by side with C and Python, and a typing rule">

```c
printf("%d\n", -7 / 2);  // -3, like Rust
```

```python
print(-7 // 2)  # -4: Python rounds down
```

C divides integers the way Rust does, but converts between number types
silently, where Rust insists on `as`; Python's `//` rounds *down*. In
Rust, `let x = let y = 6;` is an error because `let` is a statement,
where JavaScript's `x = y = 6` works because assignment is an
expression. The rule rustc applies to every call, written as a typing
rule:

```text
f : (T1, T2) → R    Γ ⊢ a : T1    Γ ⊢ b : T2
──────────────────────────────────────────
              Γ ⊢ f(a, b) : R
```

If either argument has another type, no rule applies, and that is the
moment rustc reports E0308. Because each signature is complete, rustc
can check every function body on its own, and the machine code passes
an `i32` as four bytes in a register, with no tag and no check. Your
Drip VM's `||` already compiled to a jump that leaves one value on the
stack; an `if` *expression* compiles with the same jumps as the `if`
statement, except that each branch leaves its value on the stack instead
of popping it, so being expression-oriented costs nothing at run time.

</More>

<Analogy extra title="containers in a kitchen">
You would not keep a pinch of salt in a bucket or soup in an egg cup;
each container is sized for what it holds. Rust's number types are
containers of fixed sizes: a `u8` is an egg cup (one byte), an `i64` a
saucepan (eight). Pour in more than fits and it spills, which in Rust
is called **overflow**.
<span slot="breaks">A kitchen container holds any amount up to its
brim; a Rust integer of a given type also has a fixed lowest value, and
some types cannot hold negatives at all.</span>
</Analogy>
