## A VM with no memory for names

So far the VM can work out `print (1 + 2) * 3;`, but give it this and
it has nowhere to keep `total`:

```text
let total = 10;
total = total + 5;
print total;
```

The tree-walker kept a `Map` from names to values; the VM does the
same, with the hash table of *Finding things fast*, keyed by the
interned strings of *String interning*.

## A name becomes a constant

An instruction cannot carry a string: after the opcode come only bytes.
So the compiler puts the *name* in the constant pool, as a string, and
the instruction gives its index (from `vm/compiler.ts`, line breaks
added to fit the page):

```ts
const identifierConstant =
  (name: string) =>
    makeConstant(heap.copyString(name));
```

`copyString` interns the name, so every mention of `total` refers to
the *same* string object. A helper, `emitConstantOp`, then writes the
opcode and the index in two bytes, high byte first (`(k >> 8) & 0xff`)
and low byte second (`k & 0xff`), so one function can name up to 65,536
constants. Here is how a `let` is compiled:

```ts
function letDeclaration() {
  consume('identifier',
    'a variable name after \'let\'');
  const name = previous;
  declareVariable(name);
  if (match('=')) expression();
  else emit(Op.None);
  consume(';',
    '\';\' after the variable declaration');
  defineVariable(name);
}
```

`letDeclaration` reads the name, compiles the initialiser (which leaves
its value on the stack when the program runs) or emits `none` if there
is none, checks the `;`, and calls `defineVariable`. At the top level,
that emits `define.global` with `identifierConstant(name.lexeme)` as its
operand (inside a block it does something else, the next chapter's
subject). Reading and assigning go through `namedVariable`, which emits
`load.global` or `store.global` the same way when the name is not a
local.

Here is the companion disassembler's output for a three-line program:

```text
let a = 1;
print a;
a = a + 2;
```

```text
== <script> ==
0000    1 const               0 '1'
0003    | define.global       1 'a'
0006    2 load.global         2 'a'
0009    | print
0010    3 load.global         4 'a'
0013    | const               5 '2'
0016    | add
0017    | store.global        3 'a'
0020    | pop
0021    | none
0022    | return
```

Every instruction with a constant is three bytes long (the offsets go
up by 3). The constants for `a` are 1, 2, 4 and 3: each mention adds
a pool entry, but all hold the same interned string, so the cost is a
few pool slots, not copies of the text. (In `a = a + 2` the target is
read first, so its constant, 3, comes before the right-hand side's.)
The line ends in `pop`: an assignment produces a value, and an
expression statement throws it away.

## Three instructions

Now the VM side, from the dispatch loop in `vm/vm.ts` (`readString`
reads two operand bytes and returns that constant as a string object):

```ts
case Op.LoadGlobal: {
  const name = readString();
  const v = this.globals.get(name);
  if (v === undefined)
    this.runtimeError(
      `undefined variable '${name.chars}'`);
  this.push(v!);
  break;
}
case Op.DefineGlobal:
  this.globals.set(readString(),
    this.peek(0));
  this.sp--;
  break;
```

`load.global` pushes the value stored under the name, or stops with
Drip's runtime error. `define.global` *peeks* at the value, stores it,
and only then drops it (`this.sp--`), so the value is always somewhere
a garbage collection would find it (a habit the VM keeps everywhere).
It never complains about an existing name: as in the tree-walker, a
second top-level `let` replaces the first.

<Callout kind="definition">
The VM's **global table** is one hash table (`vm.globals`) mapping
interned name strings to values. `define.global` stores the value on
top of the stack under a name and pops it; `load.global` pushes the
value stored under a name, or reports `undefined variable`;
`store.global` overwrites an *existing* name and leaves the value on
the stack. Each takes one operand: the two-byte constant index of the
name.
</Callout>

<Formal title="The three instructions">

```text
G : name ⇀ value          (the globals)
define n:  G := G[n ↦ v], pop v
load n:    push G(n)   if n ∈ dom G
store n:   G := G[n ↦ v]  if n ∈ dom G
otherwise: undefined variable 'n'
```

<span slot="read">G is a partial map (the half arrow) from names to
values: not every name has one. define sets n to v, the value on top of
the stack, and pops it. load pushes G of n if n is in G's domain, the
names it has; store replaces n's value only if n is there. Otherwise
both are a runtime error.</span>
</Formal>

<Examples of="global-table">

```text
let x;
0000    1 none
0001    | define.global       0 'x'
```

```text
b = 5;
runtime error: undefined variable 'b'
  at line 1 in script
let b = 5; # fine: this defines b
```

```text
print len;    # native fn len
let len = 3;
print len;    # 3
```

</Examples>

First, `let` with no initialiser: the compiler emits `none`, so
`define.global` always has a value to store. Second, the mistake to
know: assigning to a name no `let` defined is a runtime error, while
`let b = 5;` works. Third, a surprise: the natives are globals in the
same table, so a top-level `let len` replaces the native `len`.

## The store.global trick

Assigning to an undefined name must be an error. The obvious code looks
the name up, checks it is there, then stores: two lookups. The VM does
one:

```ts
case Op.StoreGlobal: {
  const name = readString();
  if (this.globals.set(name,
      this.peek(0))) {
    // Assigning never creates a global:
    // undo and complain.
    this.globals.delete(name);
    this.runtimeError(
      `undefined variable '${name.chars}'`);
  }
  break;
}
```

`Table.set` returns `true` when the key was *new*, which in a correct
program never happens here, so a correct assignment costs one `set`. In
a mistaken one the VM has just created a variable that should not
exist, so it deletes it (leaving a tombstone) and reports the error; a
program about to stop can afford that. There is no pop: the value
stays, because `print a = 3;` needs it.

## Found late, on purpose

A global is looked up by name *when the instruction runs*, not when it
is compiled, so a function can mention a global that does not exist yet,
as long as it exists by the time the function is called:

When `show` is compiled, `greeting` is only a string in its constant
pool; by the time `show()` runs `load.global`, the `let` has run. That
is also what lets two top-level functions call each other, whichever
comes first in the file.

## What you learned

- The compiler stores a global's **name** in the constant pool, and
  the global instructions take its index as a two-byte operand.
- The VM's **global table** is a hash table keyed by interned strings.
- `define.global` stores, then pops; `load.global` pushes or reports
  `undefined variable`; `store.global` sets first, leaves the value,
  and deletes the key again if it was new.
- Globals are found by name at run time, so a function can use a
  global defined after it; the price is a lookup on every access.

Next: local variables, which skip the table entirely.
